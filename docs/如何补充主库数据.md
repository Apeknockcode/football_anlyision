# 如何补充主库数据

主库即预测引擎依赖的**比赛与球队数据**（`teams`、`matches`、`competitions` 等）。竞彩预测时，模型用主库里的**主客队近期比分**算期望进球；主库数据越全、每队近期场次越多，「预测总进球」等数值差异越大，不会都挤在 2.0～2.1。

---

## 一、主库是什么、存在哪

- **主库** = 存 `teams`（球队）、`matches`（比赛，含比分）、`competitions`（赛事）的库。
- **存哪**：由配置决定  
  - 用 **SQLite**：`DATABASE_URL` 或默认 `data/football.db`  
  - 用 **MongoDB**：`USE_MONGO=true` 且 `MONGO_URI`、`MONGO_DB_NAME`（如 `football` 或 `self_improvement_football`）

竞彩预测会通过 `jingcai_teams` + 队名映射解析出主客队，再到主库 `teams` 里查 id，再在 `matches` 里按 `home_team_id`/`away_team_id`、`competition_id` 查**该联赛、该队**的近期比赛。所以：

- 主库要有**这些联赛的球队**（`teams`）
- 主库要有**这些联赛的已完赛比赛**（`matches`，含 `home_score`/`away_score`）

---

## 二、两种常用补数方式（二选一或都做）

### 方式一：football-data.org（五大联赛 + 欧冠等）

需在 [football-data.org](https://www.football-data.org/) 注册并配置 `FOOTBALL_DATA_API_KEY`。

```bash
# 拉取多赛季（建议至少 3～5 个赛季，近期场次才够）
python main.py ingest-fd --seasons 2022,2023,2024,2025,2026

# 只拉某一联赛
python main.py ingest-fd --seasons 2024,2025 --leagues PL

# 欧冠
python main.py ingest-fd --leagues CL --seasons 2023,2024,2025,2026
```

- 会写入：`competitions`、`seasons`、`teams`、`matches`（含未开赛；完赛后有比分）。
- 免费档有请求限制，可分批跑（如先 2024,2025 再 2022,2023）。

### 方式二：API-Football（五大联赛，与伤停/赔率/积分同源）

需配置 `API_FOOTBALL_KEY`（或 `API_FOOTBALL_KEYS`）。

```bash
# 拉取多赛季历史已完赛
python main.py ingest-api-history --seasons 2022,2023,2024,2025,2026

# 若主库是 SQLite 且希望同步到 MongoDB，可加
python main.py ingest-api-history --seasons 2024,2025,2026 --sync-mongo
```

- 会写入：`competitions`、`seasons`、`teams`、`matches`（历史完赛场次）。
- 未来赛程（用于休息天数、赛程密度）需单独拉：
  ```bash
  python main.py ingest-api-upcoming --seasons 2025,2026
  ```

## 三、补完主库后建议再做的几步

### 1. 竞彩队名能对上主库

预测前主客队要在主库 `teams` 里能按名称解析到：

```bash
# 用 API-Football 补全 jingcai_teams 的英文名与 api_football_team_id，并同步到主库 teams
python main.py jc-teams-map-api-football
```

若某联赛在主库本来就没有（例如只拉了五大联赛），需要先用上面「方式一/二」拉该联赛的赛程，主库才会有对应 `teams` 和 `matches`。

### 2. 竞彩场次回填 fixture_id（可选，便于统计/xG）

若竞彩用 API-Football 同源，可把体彩场次与 API 的 fixture 对应起来，方便后续拉单场统计、xG 等：

```bash
python main.py jc-match-analysis-backfill-fixture-id --year 2025
```

有未匹配的可在 `data/jingcai_fixture_id_override.json` 里手动补 `sporttery_match_id → fixture_id`，再跑一次上述命令。

### 3. 重新跑预测

主库补了新赛季/新联赛后，应对竞彩日重新算预测，这样「预测总进球」等才会用上新历史：

```bash
# 按日期
python main.py predict-jc-from-self-improvement --date 2026-03-07 --last-n 10

# 按年（含已完赛）
python main.py predict-jc-from-self-improvement --year 2025 --include-finished
```

## 四、快速自检

- **主库有多少场次**：  
  `python main.py data-stats`  
  会输出主库比赛数、已完赛数、预测数等。
- **某天预测为什么跳过**：  
  `python main.py predict-jc-from-self-improvement --date 2026-03-07 --include-finished --verbose`  
  会逐场标明「主队名未解析」/「客队名未解析」等。
- **预测总进球仍集中在 2.0～2.1**：  
  多半是**该场主/客队在对应联赛下近期场次仍不足**（模型会向联赛平均收缩）。可再补更多赛季、或确认该联赛已用上面方式一/二入库。

---

## 五、小结

| 目的 | 命令 |
|------|------|
| 补主库比赛（五大联赛多赛季） | `python main.py ingest-fd --seasons 2022,2023,2024,2025,2026` 或 `python main.py ingest-api-history --seasons 2022,2023,2024,2025,2026` |
| 补未来赛程 | `python main.py ingest-api-upcoming --seasons 2025,2026` |
| 竞彩队名对上主库 | `python main.py jc-teams-map-api-football` |
| 竞彩回填 fixture_id | `python main.py jc-match-analysis-backfill-fixture-id --year 2025` |
| 重新写竞彩预测 | `python main.py predict-jc-from-self-improvement --date 2026-03-07` 或 `--year 2025 --include-finished` |

更细的「新增某一年」全流程见 [新增年份数据流程.md](新增年份数据流程.md)；竞彩被跳过原因见 [竞彩预测跳过原因说明.md](竞彩预测跳过原因说明.md)。
