# 模型命中率优化指南

当前模型命中率约 40%+（胜平负三选一，随机约 33%）。以下按**性价比**排序，便于优先尝试。

---

## 一、先看现状（必做）

```bash
# 全量胜平负准确率、MAE、按联赛拆解
python3 main.py predict-eval
python3 main.py predict-eval --by-competition

# 获取「弱联赛」与调参建议（基于复盘数据）
python3 main.py suggest-improvements
```

根据 **by-competition** 结果看哪几个联赛明显偏低，再针对性调该联赛的 `last_n`、平局系数等。

---

## 二、调参与融合权重（不改代码）

在 `.env` 或 `config.py` 中可调（改完需 **repredict-history** 再评估）：

| 配置项 | 含义 | 建议尝试 |
|--------|------|----------|
| `PREDICT_ODDS_FUSION_WEIGHT_MODEL` | 模型 vs 赔率 的权重，当前 0.47 | 0.40～0.55 之间微调，略降模型多借市场信息 |
| `PREDICT_API_PREDICTIONS_WEIGHT` | API 预测融合权重，当前 0.30 | 0.25～0.40 |
| `PREDICT_OUTCOME_ML_WEIGHT` | ML 修正层权重，当前 0.26 | 0.2～0.35；样本多时可略提高 |
| `PREDICT_DRAW_BOOST_COEF` | 平局修正系数，当前 0.20 | 联赛差异大时用 `predict_league_params.json` 按联赛覆盖 |
| `PREDICT_BOUNDARY_HOME_SPREAD` | 势均力敌时「略偏主」的阈值，当前 0.28 | 0.2～0.35，减少「预测平、实际主」 |
| `PREDICT_BOUNDARY_HOME_NUDGE` | 上述情况下主队期望进球加成，当前 0.03 | 0.02～0.05 |

**操作顺序**：改 `.env` → `python3 main.py repredict-history --db-only` → `python3 main.py predict-eval --by-competition`，对比命中率。

---

## 三、按联赛调参（效果通常最明显）

编辑 `data/predict_league_params.json`，对命中率偏低的联赛单独设 `last_n`、`PREDICT_HOME_ADVANTAGE`、`PREDICT_DRAW_BOOST_COEF` 等，例如：

```json
{
  "Serie A": { "last_n": 8, "PREDICT_DRAW_BOOST_COEF": 0.18 },
  "Ligue 1": { "last_n": 6 }
}
```

然后执行：

```bash
python3 main.py repredict-history --db-only
python3 main.py predict-eval --by-competition
```

`suggest-improvements` 的输出会给出「弱联赛」及建议的 `last_n` 范围，可作参考。

---

## 四、重训 ML 修正层与校准

样本足够（建议 2000+ 已完赛且有预测）时：

```bash
# 用当前 DB 的 predictions+matches 重训胜平负 ML 修正层
python3 main.py train-outcome-ml

# 概率校准（让预测概率更接近实际频率）
python3 main.py calibrate-probs
```

重训后无需改配置，预测时会自动加载新模型/校准参数。可多试几次不同随机种子：

```bash
PREDICT_OUTCOME_ML_RANDOM_STATE=42 python3 main.py train-outcome-ml
PREDICT_OUTCOME_ML_RANDOM_STATE=99 python3 main.py train-outcome-ml
```

每次重训后跑 `repredict-history` + `predict-eval` 看哪次命中率更高。

---

## 五、补数据（赔率 / API 预测）

- **赔率**：有赔率的场次会做「模型+赔率」融合，通常更稳。  
  - 近期 7 天内可用 API-Football 补：`python3 main.py odds-api-by-db --limit 7 --rate-limit 0.05`  
  - 体彩/竞彩按日积累后关联：`normalize-team-names`、`link-match-odds`
- **API 预测**：已开启 `PREDICT_USE_API_PREDICTIONS=true` 时，对缺 API 的历史场次可跑：  
  `python3 main.py fill-api-predictions --rate-limit 0.05 --years 2024,2025`  
  融合预测会用到这些 API 结果，完赛后再看「融合」命中率是否提升。

---

## 六、可选：启用 xG / 更多特征

- **xG**：若已有或可拉取射门/射正等统计，可开启 `PREDICT_USE_XG=true`、`PREDICT_XG_BLEND=0.3`，用近期场均 xG（或近似）与形式期望进球混合，减少偶然大比分干扰。  
  详见 [可补充数据与模型提升.md](可补充数据与模型提升.md)。

---

## 七、推荐迭代流程

1. 跑 `predict-eval`、`predict-eval --by-competition`、`suggest-improvements` 记录当前命中率与弱联赛。
2. 按联赛改 `data/predict_league_params.json`，或微调 `.env` 中 `PREDICT_ODDS_FUSION_WEIGHT_MODEL`、`PREDICT_DRAW_BOOST_COEF`、边界场次相关参数。
3. 执行 `repredict-history --db-only` → `predict-eval --by-competition`，对比前后命中率。
4. 样本足够时执行 `train-outcome-ml`、`calibrate-probs`，必要时换随机种子多训几次。
5. 补赔率与 API 预测后，再 repredict + eval，观察「模型 / API / 融合」三项命中率变化。

每次改动建议只动一两项，便于归因；Web 仪表盘「更新命中率」可随时查看最新统计。

---

## 八、还能继续优化吗？——进阶与数据侧

可以。在现有调参与重训之外，还有以下方向能继续抬升命中率（按**性价比**排序）。更系统的**模型改进方向**（期望进球层、胜平负/比分层、数据特征、校准与 ML）见 [模型改进方向.md](模型改进方向.md)。

### 1. 联赛专属校准与联赛专属 ML（已实现，建议优先试）

- **联赛专属校准**：按联赛分别拟合 Platt 参数，预测时自动选用该联赛参数。  
  ```bash
  python3 main.py calibrate-probs --by-competition
  ```
  需样本中带 `competition_id`（主库/竞彩预测落库时已有）。适合「某联赛整体偏主/偏平」的情况。

- **联赛专属小模型**：对样本多的联赛单独训一个 ML 修正层，预测时优先用该联赛模型。  
  ```bash
  # 例如对 competition_id=6001 的联赛单独训练
  python3 main.py train-outcome-ml --competition-id 6001
  ```
  主模型仍用 `train-outcome-ml`（无 `--competition-id`）；预测时若该场有对应联赛模型则自动选用。

- **ML 特征扩展**：训练数据中若 match 带 `home_rank`/`away_rank`，已自动加入 `rank_diff` 特征；补全积分榜回填后重训即可：  
  `python3 main.py standings-backfill`（或 standings-api）→ `python3 main.py train-outcome-ml`。

### 2. 数据侧：覆盖越全，命中率越稳

| 数据 | 作用 | 命令/做法 |
|------|------|-----------|
| **赔率覆盖** | 有赔率则做模型+赔率融合，通常更稳 | 按日积累体彩/竞彩赔率；近期 7 天可 `odds-api-by-db --limit 7` |
| **xG/统计覆盖** | 与形式期望进球混合，减弱偶然大比分干扰 | `PREDICT_USE_XG=true`，并对评估日期范围逐日跑 `statistics-api --date YYYY-MM-DD` |
| **积分榜/排名** | 排名微调 + ML 的 rank_diff 特征 | `standings-api` 或 `standings-backfill`，保证当季 league_standings 有数据 |
| **伤停/关键球员** | 伤停下调 + 关键球员加重 | 竞彩分析页有 `match_player` 时已自动算关键球员伤停；主库用 injury-api 按日拉 |
| **更多历史赛季** | 近期场次与 H2H 更足，期望进球更稳 | `ingest-api-history --seasons 2021,2022,2023,...` 按需扩展 |

### 3. 产品侧：主推高置信度、按联赛看

- 命中率指标：重点看 **高置信度子集**（`outcome_accuracy_high_conf`）和 **按联赛**（`by_league`），全量可作为参考。  
- 产品上主推「高置信度」场次（API：`/predictions?high_confidence_only=true`），弱联赛或低置信度标为「参考」。  
- 详见 [产品与评估策略.md](产品与评估策略.md)。

### 4. 预期与节奏

- **全量 70%**：仅靠调参很难达到，需要持续补数据、联赛专属校准/ML、以及更多特征（如裁判、战意等，见 [可补充数据与模型提升.md](可补充数据与模型提升.md)）。  
- **高置信 + 头部联赛**：通常可稳住 55%～65%，适合作为「主推口径」。  
- **建议节奏**：每积累一批新完赛+预测（或补完赔率/积分榜/xG）→ `refresh-models`（或加 `calibrate-probs --by-competition`、联赛专属 `train-outcome-ml`）→ `repredict-all` → `predict-eval --by-competition` / `jc-predictions-eval`，对比前后命中率与高置信度命中率。
