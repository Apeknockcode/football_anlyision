# 阵容数据抓取设计

本文档给出「赛前预计首发」与「赛后确认阵容」两类数据的抓取思路：URL 规律、比赛列表获取、阵容字段解析，以及与现有竞彩/DB 的关联方式。实现时需遵守各站点的 robots.txt 与使用条款，并做请求频率控制。

---

## 一、赛后确认阵容：Transfermarkt

### 1.1 URL 规律

| 用途 | URL 格式 | 说明 |
|------|-----------|------|
| **单场阵容/报告** | `https://www.transfermarkt.com/spielbericht/index/spielbericht/{match_id}` | 赛后才有完整首发+替补；match_id 为数字，如 4361530 |
| **联赛某轮赛程** | `https://www.transfermarkt.com/{league_slug}/spieltag/wettbewerb/{wettbewerb_id}?saison_id={year}&spieltag={round}` | 从该页可解析出当轮所有比赛的「Match report」链接，即 match_id |

**域名**：可用 `.com` / `.de` / `.at` 等，同一 match_id 通用。

**联赛与赛季**：

- `wettbewerb_id`：联赛代码，如英超 `GB1`、德甲 `L1`、西甲 `ES1`、意甲 `IT1`、法甲 `FR1`。
- `saison_id`：赛季年（通常用开赛年），如 2024 表示 24/25 赛季。
- `spieltag`：轮次，1～38（或该联赛总轮次）。

**示例**：

- 英超 24/25 第 38 轮：  
  `https://www.transfermarkt.com/premier-league/spieltag/wettbewerb/GB1?saison_id=2024&spieltag=38`
- 单场报告：  
  `https://www.transfermarkt.com/spielbericht/index/spielbericht/4361530`

### 1.2 如何拿到比赛列表（得到 match_id）

1. **按联赛+赛季+轮次**  
   - 请求联赛 spieltag 页（如上）。  
   - 解析 HTML 中所有「Match report」链接，正则提取：`/spielbericht/(\d+)`，得到该轮全部 `match_id`。  
   - 遍历 `spieltag=1` 到最大轮次，即可得到该赛季该联赛所有比赛 ID。

2. **按日期**  
   - Transfermarkt 有「当日赛程」类页面（如 `aktuell/waspassiertheute/aktuell/new/datum/YYYY-MM-DD`），可解析当日比赛链接得到 match_id，再逐场进 spielbericht 抓阵容。

3. **与现有数据关联**  
   - 竞彩场次有 `api_football_fixture_id` 或主客队+日期；Transfermarkt 无官方 API，需通过「主客队名 + 比赛日」或第三方映射表与 TM 的 match_id 对应，或只做「按联赛+轮次批量抓」再在应用层用队名+日期匹配。

### 1.3 阵容字段解析（赛后确认）

- 在 **spielbericht** 页中，首发与替补通常在：
  - 主队/客队各一块区域，表格或列表中有球员名、号码、位置（若有）。
- 可解析内容建议：
  - **主队首发**：球员名、球衣号、位置（若页面上有）。
  - **客队首发**：同上。
  - **替补**：替补名单及是否上场（若页面有标注）。
  - **阵型**：若页面有展示（如 4-3-3），可一并解析。
- 实现方式：
  - 用 HTML 解析（如 BeautifulSoup）定位表格或带 class 的 div；若页面大量由 JS 渲染，需用浏览器自动化（Playwright/Selenium）拿到渲染后 HTML 再解析。
- 注意：TM 会改版，选择相对稳定的 class 或语义化结构，并做异常与重试。

### 1.4 数据落库建议

- 表结构可与现有 `match_lineups` 对齐或扩展：  
  `match_id`（本系统）、`source`=`transfermarkt`、`transfermarkt_match_id`、`home_starting`/`away_starting`（名单列表）、`home_substitutes`/`away_substitutes`、可选 `formation_home`/`formation_away`、`fetched_at`。
- 与竞彩场次关联：通过「比赛日 + 主队 + 客队」或「api_football_fixture_id → 第三方映射 → TM match_id」在应用层关联。

## 二、赛前预计首发：懂球帝

### 2.1 URL 规律

| 用途 | URL 格式 | 说明 |
|------|-----------|------|
| **单场预计首发/预测** | `https://m.dongqiudi.com/matchDetail/{match_id}/prediction` | 赛前预测、预计首发等 |
| **单场阵容** | `https://m.dongqiudi.com/matchDetail/{match_id}/lineup` | 阵容页，可能含预计或实际名单 |
| **比赛列表** | `https://m.dongqiudi.com/match` 或 `https://m.dongqiudi.com/match/10` 等 | 按赛事/日期展示比赛，需从列表进入各场拿到 match_id |

**match_id**：懂球帝自有的比赛 ID，数字，如 54149134、53064517。与体彩 `sporttery_match_id`、API-Football `fixture_id` 不同，需单独维护或通过「日期+主客队」匹配。

### 2.2 如何拿到比赛列表（得到 match_id）

1. **从列表页/赛事入口**  
   - 请求 `m.dongqiudi.com/match` 或具体赛事子路径（如 `/match/10`）。  
   - 若为前端渲染，需用浏览器自动化或抓取前端请求的接口（如返回 JSON 的 API），从返回中解析每场比赛的 `match_id`（或详情链接中的 ID）。

2. **按日期**  
   - 若懂球帝有「按日期赛程」的接口或页面，可解析该日所有比赛 ID；否则从「今日/本周」等入口逐层解析。

3. **与竞彩/DB 关联**  
   - 竞彩场次有 `sporttery_match_id`、主客队中文名、`jc_date`。  
   - 需在懂球帝列表或详情中通过「比赛日 + 主队名 + 客队名」模糊匹配到懂球帝的 `match_id`，再请求该场的 `/prediction` 或 `/lineup`。

### 2.3 阵容字段解析（赛前预计）

- **/prediction** 页：多为「预计首发」、阵型、可能带球员名列表。  
  - 解析目标：主队预计 11 人、客队预计 11 人（若有）；阵型文案（如 4-3-3）；若页面有「不确定」或替补预测，可酌情存为备注。
- **/lineup** 页：可能含预计或实际阵容。  
  - 解析目标：同上，主/客名单 + 阵型；若赛前为预计、赛后为实际，可用「抓取时间 vs 开球时间」或页面标签区分。
- **注意**：懂球帝**并非所有比赛都有赛前阵容**。不少场次（尤其女足、非顶级联赛或关注度较低的赛事）在赛前「阵容」页会显示「**暂无阵容信息**」，即无预计首发可抓。赛前逻辑若依赖懂球帝，只能覆盖有数据的场次，其余场次无法做「预计首发缺阵」叠加。
- 实现：  
  - 若为服务端渲染，直接解析 HTML 中的名单块。  
  - 若为接口数据，可抓前端请求的 API（如 `/matchDetail/xxx/prediction` 或类似），解析 JSON 中的阵容数组，通常更稳定。

### 2.4 数据落库建议

- 可与 `match_lineups` 扩展：  
  `source`=`dongqiudi`、`dongqiudi_match_id`、`lineup_type`=`predicted`|`confirmed`、主客队名单字段、`fetched_at`、可选 `match_date`/`home_team`/`away_team` 用于与竞彩匹配。
- 赛前预计与赛后确认可同表用 `lineup_type` 区分，或分表存储，便于和 Transfermarkt/API-Football 的「赛后确认」合并使用。

## 三、与现有系统的衔接

- **赛后确认**：Transfermarkt 抓到的阵容可写入/更新 `match_lineups`（或扩展表），通过「比赛日+主客队」或「fixture_id 映射」与 `jingcai_match_analysis`/`jc_predictions` 关联；用于阵容稳定性、关键球员缺阵等特征时，再与伤停、射手名单结合。
- **赛前预计**：懂球帝数据可作为「预计首发」单独存储，用于赛前展示或简单对比（如与伤停名单对比「预计缺阵」）；若需参与模型，需再定义如何从「预计名单」推导缺阵/轮换特征并传入 `predict_match`。
- **去重与频率**：同一场同来源只保留最新一条或按 `fetched_at` 覆盖；请求间隔建议 1～3 秒/页，避免封 IP。

## 四、小结

| 来源 | 类型 | URL 关键 | 比赛列表 | 解析要点 |
|------|------|----------|----------|----------|
| **Transfermarkt** | 赛后确认 | `/spielbericht/index/spielbericht/{match_id}` | 联赛 spieltag 页或按日赛程页中提取 match_id | 主客首发+替补+阵型，HTML 或浏览器渲染后解析 |
| **懂球帝** | 赛前预计（及部分阵容） | `/matchDetail/{match_id}/prediction`、`/lineup` | 从 match 列表/赛事页或前端 API 解析 match_id | 预计首发名单+阵型；可优先抓接口 JSON |

实现时建议先做「单场解析」验证字段稳定性，再做「比赛列表 → 批量抓取 → 落库 → 与竞彩/DB 关联」的流程；若某站改版导致选择器失效，只需调整解析层即可。

## 五、阵容数据源：以 API-Football 为主；懂球帝/TM 赛前预计为可选

**当前策略**：**先拉取赛后阵容数据**（API-Football → `lineups-by-jingcai` → `match_lineups`），用于展示、复盘、统计。懂球帝、Transfermarkt 因抓取不稳定不予使用；**赛前阵容数据后续再处理**（若接入新源或 API 再考虑是否参与预测）。若将来启用懂球帝/TM 赛前预计，可在 `.env` 中设置 `JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true`。

**进模型逻辑**（当 `JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true` 时）：`parse_jingcai_analysis_for_predict` 中按 `sporttery_match_id` 先查懂球帝阵容，无则再查 Transfermarkt；若该场有预计首发，则关键球员中「不在预计首发且未在伤停名单」的人数叠加到 `home_absent_key_count` / `away_absent_key_count`。

### 5.1 Transfermarkt（赛前用户阵型，回退）

- **落库**：集合 `transfermarkt_lineups`，按 `sporttery_match_id` 唯一；字段含 `predicted_home_starting`、`predicted_away_starting`、`jc_date`、`home_cn`、`away_cn`、`transfermarkt_match_id`、`formation_home`、`formation_away`。
- **数据来源**：赛前预览页 **vorbericht**（`/vorbericht/index/spielbericht/{match_id}`）中的「User's formations」——用户提交的预计阵型与 11 人名单，非官方确认首发。
- **抓取**：`etl/transfermarkt_lineups.py`。先请求当日赛程页 `aktuell/waspassiertheute/aktuell/new/datum/YYYY-MM-DD` 解析 match_id（及尽量解析主客队名），与竞彩场次按主客队名（优先英文）模糊匹配；再请求各场 vorbericht 解析两队 11 人 + 阵型。若当日程页无队名，则按 match_id 逐个请求 vorbericht 用页内队名匹配。
- **命令行**：`python3 main.py transfermarkt-lineups [--date YYYY-MM-DD] [--no-save] [--rate-limit SEC] [--max-matches N]`。默认当天竞彩日，先读 `jingcai_match_analysis` 或 `jc_matches` 该日场次，再拉 Transfermarkt 并落库。
- **防封禁**：`.env` 中 `TRANSFERMARKT_RATE_LIMIT_SEC`（默认 2.5 秒）、`TRANSFERMARKT_MAX_REQUESTS_PER_RUN`（默认 25 场/次）；`--rate-limit`、`--max-matches` 可覆盖。建议保持 2～5 秒间隔，避免短时间多次跑满上限。

#### Transfermarkt 人机验证（CAPTCHA）说明

**无法真正「跳过」验证**：破解或自动识别 CAPTCHA 违反站点条款且涉及合规风险，不应使用。

**可做的只有两件事**：

1. **尽量少触发验证**（降低被当成机器人的概率）  
   - 已做：请求头带 `User-Agent`、`Accept-Language`（如 en-US, de）、`Referer`（站内来源），与当前实现一致。  
   - 建议：把 `TRANSFERMARKT_RATE_LIMIT_SEC` 调到 **5～15 秒**，`TRANSFERMARKT_MAX_REQUESTS_PER_RUN` 调到 **10～15**，单日少跑、分散到多天。  
   - 可选：用 **Playwright 等真实浏览器** 代替 `requests` 发请求——站点对真实浏览器有时不弹验证；实现成本高，需维护浏览器与选择器。

2. **验证出现时的合规做法**  
   - **方式 A**：用 Playwright 非无头模式跑脚本，验证弹出时**人工在浏览器里点一次**，通过后脚本继续。  
   - **方式 B**：不处理验证，本次抓取失败，改用懂球帝或其它赛前阵容源。

**结论**：若 Transfermarkt 在你环境下经常 405/人机验证，建议以懂球帝或付费 LineupAPI/Sportmonks 为主，TM 仅作可选回退。

### 5.2 懂球帝（赛前预计首发，主源）

- **落库**：集合 `dongqiudi_lineups`，按 `sporttery_match_id` 唯一；字段同 5.1 结构（`predicted_home_starting`、`predicted_away_starting` 等），键名为 `dongqiudi_match_id`。
- **抓取**：`etl/dongqiudi_lineups.py`，请求 `m.dongqiudi.com/match` 解析 match_id，再请求 `/matchDetail/{id}/prediction` 或 `/lineup` 解析预计首发；与竞彩场次按主客队名模糊匹配。
- **命令行**：`python3 main.py dongqiudi-lineups [--date YYYY-MM-DD] [--no-save] [--rate-limit SEC] [--max-matches N]`。
- **防封禁**：`DONGQIUDI_RATE_LIMIT_SEC`（默认 2.5 秒）、`DONGQIUDI_MAX_REQUESTS_PER_RUN`（默认 25）；同上建议。

## 附录：懂球帝比赛 ID 的获取与 API 破解

- **比赛列表**（当 HTML 列表页为前端渲染、解析不到链接时）：  
  - 使用 **sport-data.dongqiudi.com** 的 schedule API 按日期聚合：  
    - `GET /soccer/biz/data/seasons?competition_id={id}` 取赛季，联赛 ID 与 m.dongqiudi.com/stat/N 一致：**英超=1、意甲=2、西甲=3、德甲=4、欧冠=5、法甲=10**；  
    - `GET /soccer/biz/data/schedule?season_id=...&round_id=...&gameweek=k` 取该轮场次，过滤 `date_utc == jc_date`。  
  - 实现见 `etl/dongqiudi_lineups.py` 中 `fetch_match_list_by_date_api(jc_date, ...)`，默认请求上述 6 个联赛、gameweek 26～30 及前 2 个赛季以覆盖目标日。
- **单场阵容**（优先用 API，再回退 HTML）：  
  - **API**：`GET api.dongqiudi.com/data/detail/match/{match_id}`，响应中 `matchFormation.team_A/B.lineups` 为首发、`sub` 为替补（球员名在 `person` 字段）。  
  - 实现见 `fetch_match_detail_api(match_id)`；`fetch_prediction_for_match` 先调该 API，无阵容再请求 `m.dongqiudi.com/matchDetail/{id}/prediction` 或 `/lineup` 解析 HTML。
- 与竞彩场次关联：仍用「比赛日 + 主队中文名 + 客队中文名」与懂球帝列表（来自 HTML 或 schedule API）模糊匹配，取 `match_id` 后请求详情/阵容。

## 六、三种阵容数据源对比

| 维度 | 懂球帝 | Transfermarkt | API-Football |
|------|--------|----------------|--------------|
| **数据类型** | 赛前**预计首发**（预测/编辑产出） | 赛前**用户阵型**（vorbericht）或 赛后**确认阵容**（spielbericht） | 赛后**确认阵容**（官方数据） |
| **获取方式** | 爬虫（HTML 解析），无官方 API | 爬虫，无官方 API；网页/接口易被 405 或人机验证拦截 | **官方 API**（`fixtures/lineups`），需付费 Key |
| **覆盖范围** | 以国内关注赛事为主，列表页可能前端渲染，需按队名匹配竞彩；**不少场次赛前无阵容**（显示「暂无阵容信息」） | 欧洲主流联赛；按联赛轮次或当日页取 match_id，再与竞彩队名匹配 | 与 API 订阅一致（如五大联赛等），按 `fixture_id` 精确关联 |
| **稳定性** | 依赖页面结构；列表/预测页改版会导致解析失败 | 依赖页面结构；当前访问受限（405/人机验证），实际可用性差 | 接口稳定，有文档与版本约定；受配额与 Key 限制 |
| **字段丰富度** | 主/客预计首发名单（球员名）、阵型（若有） | 主/客 11 人名单、阵型（如 4-3-3）；赛后页可有号码、位置、替补 | 首发 + 替补，每项含 `player_id`、`player_name`、`number`（号码），便于与球员库关联 |
| **落库位置** | `dongqiudi_lineups`（按 `sporttery_match_id`） | `transfermarkt_lineups`（按 `sporttery_match_id`） | `match_lineups`（按主库 `match_id`，即 API 的 fixture 对应比赛） |
| **在本项目中的用途** | **预测阶段**（可选）：仅当 `JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true` 时读取，叠加「关键球员未在预计首发」到 key_count；默认关闭 | 同上，作懂球帝回退 | **主源**：赛后实际阵容，展示/复盘/统计；竞彩落库 `self_improvement_football.match_lineups`（`lineups-by-jingcai`） |
| **关联竞彩方式** | 比赛日 + 主客队名（中文）模糊匹配懂球帝 match_id | 比赛日 + 主客队名（英文/德文等）模糊匹配 TM match_id，或联赛轮次页 | 竞彩场次需有 `api_football_fixture_id`，与 API 的 fixture 一一对应 |
| **成本与限制** | 免费；需控制频率防封，列表页可能拿不到链接 | 免费；当前难以稳定访问，需浏览器自动化或换环境 | 付费 API；每日调用配额（如 7500 次/天），适合断点续拉、按 DB 比赛批量拉 |

**小结**：

- **阵容数据以 API-Football 为主**：赛后实际阵容落库 `match_lineups`（竞彩用 `lineups-by-jingcai`），用于展示、复盘、场均首发统计等。
- **懂球帝/TM 赛前预计首发**：默认**不参与**预测（`JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=false`）。若设为 `true`，预测时会读取懂球帝（回退 TM），把「关键球员未在预计首发」叠加到 key_count；懂球帝并非所有场次都有赛前阵容。
- **赛后复盘/展示**：以 API-Football（match_lineups）为准；阵容对比中的「预计」列在未启用懂球帝/TM 时多为空。

## 七、其他可参考的阵容数据源

在懂球帝、Transfermarkt 难以稳定拿到数据时，可考虑以下来源（赛前预计 vs 赛后确认、免费 vs 付费、API vs 爬虫需自行评估）。

### 7.1 赛前预计首发（可拉取的来源）

| 来源 | 类型 | 说明 | 获取方式 | 备注 |
|------|------|------|----------|------|
| **LineupAPI** (lineupapi.com) | 赛前预计 | 五大联赛**预计首发**，约 17 天预测、按球员预测首发/分钟/进球等 | **付费**订阅，CSV 或 API，无需自写爬虫 | 非官方预测，可能有最后一刻变动；适合批量、自动化 |
| **Sportmonks** | 赛前预计 | **Premium Expected Lineups**，赛前预计首发（结合伤停、状态、战术等） | **付费** API，按 team / 按 player 端点 | 需单独订阅该高级端点；覆盖较全 |
| **懂球帝** | 赛前预计 | 国内常用，部分场次有编辑/预测首发 | 爬虫或非公开 API（本项目已实现 schedule + detail 接口） | 列表页前端渲染、联赛 ID 需对齐、非全部场次有阵容 |
| **Transfermarkt** | 赛前用户阵型 | 赛前预览页 **vorbericht** 中「User's formations」用户提交的 11 人 | 爬虫（HTML 或请求接口） | 当前访问易 405/人机验证，稳定性差 |
| **Sofascore / FotMob** | 赛前预计 | 部分比赛有 Predicted lineups 区块 | 无官方 API，需**爬虫**或抓包移动端接口 | 页面/接口会改版，维护成本高 |
| **联赛/媒体官网** | 赛前预计（非结构化） | 英超官网、OneFootball、各队跟队记者 Predicted line-ups 文章 | 爬虫或手工；多为图文/表格 | 适合少量场次、非全自动 |

### 7.2 赛后阵容（可与赛前对比、做复盘）

| 来源 | 类型 | 说明 | 获取方式 | 备注 |
|------|------|------|----------|------|
| **API-Football** | 赛后确认 | `fixtures/lineups`，首发+替补+阵型 | **付费** API，本项目已用 | 稳定、按 fixture_id 精确关联，适合主源 |
| **football-data.org** | 赛后阵容 | Match 资源 `lineup`、`bench`、`formation`；请求头 `X-Unfold-Lineups: true` | 官方 API（v4），项目已用其拉赛程 | 免费档需 Key；阵容多为**赛后**，赛前是否有取决于上游 |
| **WhoScored / FlashScore** | 赛后为主 | 阵容、阵型、球员评分 | 无官方 API，需爬虫（Selenium/Playwright） | 有开源爬虫项目，注意合规与频率 |

### 7.3 建议

- **赛前预计阵容**：  
  - 愿付费、要稳定 → **LineupAPI** 或 **Sportmonks Expected Lineups**。  
  - 免费、能接受不稳定 → 继续用 **懂球帝**（有就有、没有就跳过），或 **Transfermarkt**（需能访问且能过验证）。  
- **赛后阵容**：以 **API-Football** 为主，可选 **football-data.org** 作同源补充。  
- **爬虫类**（Sofascore、WhoScored、FlashScore）：投入大、易改版，仅作技术备选。
