# 竞彩预测命中率优化（优先胜平负）

基于 `jingcai_match_analysis` 与 `jc_predictions` 的评估与优化流程，**优先提升胜平负命中率**。

---

## 一、批量预测与评估

### 1. 对历史数据写预测（含已完赛，用于回测）

```bash
# 2025 年全年
python3 main.py predict-jc-from-self-improvement --year 2025 --include-finished

# 2026 年 2 月（日期区间）
python3 main.py predict-jc-from-self-improvement --dates 2026-02-01,2026-02-28 --include-finished
```

`--include-finished` 会对已完赛场次也写入预测，便于与真实比分对比。

### 2. 查看胜平负 / 精确比分命中率

```bash
# 按年
python3 main.py jc-predictions-eval --year 2025
python3 main.py jc-predictions-eval --year 2026

# 按日期区间（如只看 2026 年 2 月）
python3 main.py jc-predictions-eval --date-from 2026-02-01 --date-to 2026-02-28
```

输出包含：总场次、胜平负猜对数/命中率、精确比分命中率、**按联赛**的命中率；以及**让球胜平负**单独统计（有让球数且已完赛的场次中：按赔率最低项“预测”的命中率、按模型预测比分+让球数推导的命中率及按联赛拆解），便于单独看让球表现。

### 3. 让球胜平负单独看

- 命令 `jc-predictions-eval` 会输出 **【让球胜平负】** 小节：仅统计「有让球数且已完赛」的场次。
- **按赔率最低项**：用让球三项赔率中最低的那项当作“预测”，看与实际让球结果一致的占比。
- **按模型推导**：用当前模型的预测比分 + 让球数，推出让球主/平/客，与实际让球结果对比。
- 若胜平负命中率一般但让球（赔率或模型推导）命中率更高，可侧重参考让球玩法的推荐或后续单独优化让球逻辑。

---

## 二、命中率偏低时怎么办

- **看高置信度子集**：只关注「推荐概率≥45%」的场次，命中率通常高于全量；可只做高置信度推荐。
- **按联赛区分**：头部联赛与弱联赛分开看，弱联赛可标为「参考」或单独调参（见下节）。
- **单独看让球**：用 `jc-predictions-eval` 的让球胜平负统计，评估让球玩法的表现，再决定是否主推让球或加强让球模型。
- **补数据与调参**：确保赔率、伤停、未来场次已接入预测（见 [基于现有数据提高竞彩命中率.md](基于现有数据提高竞彩命中率.md)），并做联赛调参、ML 重训与校准。

---

## 三、当前基线与调参后必做

- 全量 / 按年命中率可在竞彩仪表盘「jc_predictions 模型预测统计」查看；命令行用 `jc-predictions-eval --year 2026` 等。
- **调参或改配置后**：必须对历史数据**重新写预测**再评估，否则命中率不会变。**推荐主库与竞彩一起更新**（一次命令同时更新两处）：
  ```bash
  python3 main.py refresh-and-eval
  ```
  或只重算不跑评估：`python3 main.py repredict-all --years 2025,2026`。若只需更新主库、不更新竞彩，可用 `refresh-and-eval --db-only` 或单独 `repredict-history`。
  再点仪表盘「更新命中率」或执行 `jc-predictions-eval` 查看新命中率。

---

## 四、优先胜平负的调参方向

竞彩预测使用与主库相同的 `predict_match`，因此 **主库的全局/联赛参数与校准、ML 修正层** 会一并影响竞彩命中率。

### 1. 按联赛调参（优先做）

根据 `jc-predictions-eval` 的「按联赛」结果，对命中率偏低的联赛在 `data/predict_league_params.json` 中单独设置：

- `last_n`：该联赛参考最近 N 场（可试 6～12）
- `PREDICT_DRAW_BOOST_COEF`：平局修正（如 0.15～0.25）
- `PREDICT_HOME_ADVANTAGE`：主场优势

联赛英文名需与主库 `competitions.name` 一致（如 Serie A、Premier League、Primera División）。竞彩列表中的「意甲」「英超」等会通过 `LEAGUE_MAP` 转成英文名再参与预测。

### 2. 全局参数（.env / config.py）

与 [模型命中率优化指南.md](模型命中率优化指南.md) 一致，重点可调：

- `PREDICT_ODDS_FUSION_WEIGHT_MODEL`：模型与赔率融合权重（0.4～0.55）
- `PREDICT_DRAW_BOOST_COEF`：全局平局系数
- `PREDICT_BOUNDARY_HOME_SPREAD` / `PREDICT_BOUNDARY_HOME_NUDGE`：势均力敌时略偏主，减少「预测平、实际主」

### 3. 重训 ML 修正层与校准（样本足够时）

主库有足够「已完赛 + 有预测」场次时：

```bash
python3 main.py train-outcome-ml
python3 main.py calibrate-probs
```

重训后无需改配置，竞彩预测会自动用到新的 ML 与校准结果。

---

## 五、调参后如何看竞彩命中率是否提升

1. 修改 `predict_league_params.json` 或 `.env` 后，**主库+竞彩一起重算**（推荐）：
   ```bash
   python3 main.py repredict-all --years 2025,2026
   ```
   或直接跑「重算+评估」：`python3 main.py refresh-and-eval`。若只重算竞彩某年/某区间，可单独：
   ```bash
   python3 main.py predict-jc-from-self-improvement --year 2025 --include-finished
   python3 main.py predict-jc-from-self-improvement --dates 2026-02-01,2026-02-28 --include-finished
   ```
2. 再跑评估，对比胜平负命中率与按联赛结果：
   ```bash
   python3 main.py jc-predictions-eval --year 2025
   python3 main.py jc-predictions-eval --date-from 2026-02-01 --date-to 2026-02-28
   ```

建议每次只改一两项（例如只调一个联赛或只调一个全局参数），便于归因。

## 六、所有联赛 vs 当前能预测到的联赛

- **预测逻辑已是「所有联赛」**：不会按五大联赛过滤，`jingcai_match_analysis` 里每一场都会尝试预测。
- **能写入预测的前提**：主客队必须在主库 **`teams`** 表中能解析到。队名通过 `data/jingcai_team_name_mapping.json` 与 `jingcai_teams` 映射到主库英文名后，若主库没有该队记录，仍会跳过（原因：「主队名未解析」/「客队名未解析」）。
- 因此：**主库若只入了五大联赛的球队与比赛**，则只有五大联赛（及共用同一批球队的杯赛）会有模型预测；**日职、韩职、澳超、德乙、荷甲等** 要出预测，需要先把这些联赛的 **teams + matches** 入库（如用 API-Football 等 ingest 对应联赛），再跑 `predict-jc-from-self-improvement`。
- `LEAGUE_MAP`（`etl/sporttery_crawl.py`）已扩展日职、韩职、澳超、德乙、荷甲、英冠、欧冠等；主库有对应赛事时 comp_id 会正确解析。
- 若某联赛「跳过」很多，可先跑 `python3 main.py jc-teams-map-api-football` 并补全 `jingcai_team_name_mapping.json`；若主库仍无该联赛球队，需先做该联赛的 ingest 再重跑批量预测。

## 七、进一步提升命中率（冲 70%）

- **ML 修正层权重**：已默认 `PREDICT_OUTCOME_ML_WEIGHT=0.35`（原 0.26），ML 训练集准确率约 60% 时适当提高权重可提升整体命中率。可通过 `.env` 微调（如 0.4）。
- **ML 模型已加强**：`engine/outcome_ml.py` 中 GradientBoosting 已改为 `n_estimators=80, max_depth=3`，需**重新训练**后新预测才会生效：
  ```bash
  python3 main.py train-outcome-ml
  ```
  再重跑竞彩预测与评估。
- **高置信度命中率**：评估与仪表盘已增加「高置信度（推荐概率≥45%）」统计。**只做高置信度场次的推荐时，命中率通常明显高于全量**，可作为「精选推荐」的参考；全量 70% 难度很大，高置信度子集更容易接近或超过 70%。
- **只推荐高置信度**：前端或策略上可只展示/只下注「max(胜/平/负概率) ≥ 0.45 或 0.5」的场次，用数量换命中率。
- **更多数据与特征**：引入 xG、伤停、赛程密度、联赛专属 ML 或校准、更多历史样本，都有助于继续提升；70% 全量需模型与数据双管齐下。

---

## 八、全量 70% 很难时如何对待

当前在**规则 + ML + 校准**都上的前提下，头部联赛约 56%～65%，全量到 70% 单靠调参很难达到，需要**更多特征或数据**。建议从「产品策略」和「技术路线」两方面处理。

### 1. 产品策略（立即可用）

| 做法 | 说明 |
|------|------|
| **用高置信度子集当「推荐」** | 只展示或只下注「推荐概率 ≥ 45%（或 50%）」的场次；高置信度命中率通常高于全量，更容易接近或超过 70%。仪表盘与评估已支持 `outcome_accuracy_high_conf`。 |
| **按联赛区分展示** | 头部联赛 56%～65% 已可单独展示；长尾联赛可标为「参考」或降低权重，避免全量数字拖累观感。 |
| **明确预期** | 对外/对内说明：全量 70% 为长期目标，当前以「头部联赛 + 高置信度」作为主推口径，全量作为参考。 |

### 2. 技术路线（冲 70% 需补的特征/数据）

优先做**已有数据源、易接入**的项（详见 [可补充数据与模型提升.md](可补充数据与模型提升.md)）：

1. **xG 或射门/射正近似**：`PREDICT_USE_XG`、`PREDICT_XG_BLEND` 已存在，把 API-Football statistics 按场次关联并算近期场均 xG 后传入 `predict_match`，再评估对命中率的影响。
2. **赛程密度 / 连续客场**：基于现有赛程算「未来 N 天比赛数、是否连续客场」，与休息天数一起参与疲劳/战意系数。
3. **单场统计聚合**：射门、控球、角球等近期均值 → 作为风格/压制力特征，先小权重或仅复盘用。
4. **实际进球 − xG（运气/把握能力）**：xG 接入后顺带算，作为轻量修正或展示。
5. **联赛专属校准或 ML**：按 `competition_id` 分联赛拟合校准参数或单独小模型（数据多的联赛先做）。
6. **更多历史样本**：多赛季 ingest、补历史赔率与伤停，样本增多后重训校准与 ML，再配合联赛调参。

### 3. 日常可执行的命令

- 评估全量 + 按联赛 + 高置信度：`python3 main.py jc-predictions-eval --year 2025`（及仪表盘「更新命中率」）。
- 调参/补数后重写预测再评估：**主库+竞彩一起更新**用 `refresh-and-eval` 或 `repredict-all --years 2025,2026`，再跑 `jc-predictions-eval`。
- 改进建议（弱联赛、数据与调参）：`python3 main.py suggest-improvements`。
- 重训 ML/校准：`python3 main.py train-outcome-ml`、`python3 main.py calibrate-probs`。

**结论**：全量 70% 不追求一次性到位，用「高置信度 + 头部联赛」稳住可解释的命中率，同时按上面优先级逐步加特征与数据，再评估全量是否缓慢上移。
