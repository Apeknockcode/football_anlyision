# 竞彩评估对比与伤停微调建议

用于在「优化前后」或「备份 vs 当前」之间对比命中率，并据此决定是否、以及如何按联赛微调伤停权重（`PREDICT_INJURY_KEY_PLAYER_WEIGHT`）。

---

## 1. 如何得到「优化前 / 优化后」基线

### 优化后（当前库）

在当前库、当前预测结果下导出基线：

```bash
python3 main.py jc-predictions-eval --date-from 2024-01-01 --date-to 2026-12-31 --export-baseline data/jc_eval_after.json
```

得到 `data/jc_eval_after.json`，内含：场次 n、胜平负/单场推荐/精确比分命中率、高置信命中率、**各档位**（推荐≥50%/55%/60%/65%/70%/72%/75%）的命中率与样本数、让球相关指标等。

### 优化前（备份库）

若你曾用**备份库**做对比：

1. 恢复备份到临时库或当前库；
2. 用**同一时间范围**跑评估并导出：

   ```bash
   python3 main.py jc-predictions-eval --date-from 2024-01-01 --date-to 2026-12-31 --export-baseline data/jc_eval_before.json
   ```

3. 保存好 `data/jc_eval_before.json`（可拷出备份），再恢复回「当前」库继续开发。

这样你就有一对 **before / after** 的基线 JSON，用于下面对比。

---

## 2. 如何运行对比

```bash
python3 main.py jc-eval-compare --before data/jc_eval_before.json --after data/jc_eval_after.json
```

输出包括：

- **总表**：场次、胜平负命中率、单场推荐命中率、精确比分、高置信(≥45%)、让球等，以及「推荐≥50%～75%」各档命中率；每行有「优化前 / 优化后 / 变化 / 结论（提升/下降/持平）」。
- **【变化最大的档位】**：按「变化绝对值」排序，列出前 5 个档位（如 推荐≥70% 命中率 -3.2% ↓），便于判断是哪一档被伤停或其它改动影响最大。

---

## 3. 如何看「哪些档位变化最大」

- **看总表**：先看「单场推荐命中率」「高置信(≥45%)命中率」是提升还是下降。
- **看档位**：重点看 **推荐≥65%、≥70%、≥72%、≥75%** 这几档：
  - 若**高档位**（如 ≥70%、≥75%）命中率明显**下降**：说明改动（例如伤停权重调高）可能让模型在高置信区间更保守或偏向错了，可考虑**降低伤停权重**或只对部分联赛微调。
  - 若**低档位**（如 ≥50%、≥55%）下降而高档位提升：可能是整体分布变了，高置信子集更准但全量略降，可按业务取舍（例如只推高置信）。
- **看「变化最大的档位」块**：优先处理变化绝对值最大的 1～2 档；若多数是「下降」，建议先回退伤停权重或减小上调幅度。

---

## 4. 按联赛伤停权重的微调建议

### 4.1 默认与回退

- 全局默认：`PREDICT_INJURY_KEY_PLAYER_WEIGHT = 3.0`（config 或未在联赛里覆盖时）。
- **若整体命中率下降**：建议先把**所有联赛**的伤停权重统一回退到 **3.0**（在 `data/predict_league_params.json` 里把各联赛的 `PREDICT_INJURY_KEY_PLAYER_WEIGHT` 都改为 3.0 或删掉该键），再重新跑预测与评估，看命中率是否恢复。

### 4.2 按联赛「小幅」上调（建议单次 +0.15～0.25）

- 伤停分析（`lineup-key-absent-analysis`）会给出各联赛的 **mean_diff** 与 **suggested_PREDICT_INJURY_KEY_PLAYER_WEIGHT**。  
- **不建议**一次性把建议权重全量写入（尤其不要直接写到 4.0）：容易导致命中率下降（过度惩罚关键缺阵）。
- **建议**：
  - 只对 **mean_diff 明显偏负**（预计缺阵系统性低于实际关键缺阵）、且样本量足够的联赛做微调。
  - 单次上调幅度控制在 **0.15～0.25**，例如：3.0 → 3.15 或 3.25，观察一轮评估后再考虑是否再微调。
  - 若某联赛已经 3.25，可谨慎试 3.4，避免一步到 3.5/4.0。

### 4.3 操作流程建议

1. **先回退**：全联赛伤停权重统一 3.0，跑 `predict-jc-from-self-improvement`（含 `--include-finished`）与 `jc-predictions-eval`，确认基线命中率。
2. **再对比**：若有 before（例如备份导出的 `jc_eval_before.json`），用 `jc-eval-compare` 看当前（after）与之前的差异，重点看「变化最大的档位」。
3. **按联赛小步**：根据 `lineup-key-absent-analysis --export-injury-params` 的导出结果，只对 1～2 个联赛把权重从 3.0 提到 3.15 或 3.25，合并进 `predict_league_params.json`（`merge-injury-params`），再跑预测与评估；若命中率稳定或提升，再逐步扩大范围或小幅加码。

## 5. 相关命令速查

| 目的               | 命令 |
|--------------------|------|

## 6. 修正首发阵容与命中率下降

### 6.1 数据流说明（谁影响预测、谁只影响复盘）

| 数据 | 用途 | 是否参与当次预测 |
|------|------|------------------|
| **jingcai_match_analysis**（伤停、关键球员、赔率等） | 预测时解析为 home_absent_key_count / away_absent_key_count 等 | ✅ 是 |
| **懂球帝/Transfermarkt 预计首发**（dongqiudi_lineups / transfermarkt_lineups） | 当 `JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true` 时，把「关键球员不在预计首发」额外算进 key_count | ✅ 是 |
| **match_lineups 实际首发**（lineups-by-jingcai、lineup-backfill-key-absence 写入） | 复盘、lineup-comparison、lineup-key-absent-analysis | ❌ 否 |

因此：**只修正「实际首发」并写回 match_lineups，不会改变已有 jc_predictions，也不会改变命中率**。命中率变低通常是因为**重新跑了一次预测**，且这次预测的**输入**和之前不同。

### 6.2 可能导致命中率下降的原因

1. **预计首发参与 key_count（最常见）**  
   配置 `JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true`（默认开）时，会用懂球帝/TM 的**预计首发**把「关键球员未在预计首发」叠加到 key_count，从而加重伤停惩罚。若今天**新增或修正了**预计首发数据，或关键球员名单/解析有变，key_count 会变高 → 模型更偏向弱势方 → 若这些“额外缺阵”经常不准，整体命中率可能下降。

2. **伤停权重或联赛参数**  
   若按联赛调高过 `PREDICT_INJURY_KEY_PLAYER_WEIGHT`（如 3.5、4.0），或刚改回 3.0 后又重跑预测，都会改变预测结果与命中率。

3. **jingcai 文档内容变化**  
   若对 jingcai_match_analysis 的伤停、关键球员等做了修正或重新拉取，解析出的 key_count 会变，进而影响预测。

### 6.3 建议排查步骤

1. **先试关闭「预计首发」参与 key_count**（排除是否因预计首发导致过度惩罚）  
   在 `.env` 中设置：
   ```bash
   JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=false
   ```
   然后**重新跑预测**（同一时间范围）再跑评估：
   ```bash
   python3 main.py predict-jc-from-self-improvement --date-from 2024-01-01 --date-to 2026-12-31 --include-finished
   python3 main.py jc-predictions-eval --date-from 2024-01-01 --date-to 2026-12-31
   ```
   若命中率明显回升，说明此前「预计首发叠加 key_count」偏多，可长期关掉或只对部分联赛开启。

2. **确认是否重跑过预测**  
   若没有重跑预测，只是修正了 match_lineups 实际首发，评估结果不应变化；若变了，说明做过重跑或评估范围/数据源有变。

3. **伤停权重**  
   已全联赛回退到 3.0 时，若仍觉得命中率低，可再对比「关掉预计首发」前后两次评估，区分是伤停权重还是预计首发的影响。

---

*文档与 `jc-eval-compare` 的「变化最大的档位」输出配套使用，便于根据档位变化决定是否、以及如何按联赛微调伤停权重。*
