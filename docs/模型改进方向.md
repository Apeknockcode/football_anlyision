# 模型改进方向

在现有「近期形式 + Dixon-Coles + 校准 + ML + 赔率/API 融合」基础上，可从**期望进球层**、**胜平负/比分层**、**数据与特征**、**后处理与评估**四块做改进。按性价比与实现难度排序，便于排期。

---

## 一、当前模型结构（简要）

| 层级 | 已实现 | 说明 |
|------|--------|------|
| **期望进球** | 主客近期（主主场/客客场）、历史交锋融合、联赛收缩、主场优势、疲劳/赛程密度、伤停、积分榜微调、xG 混合、边界略偏主 | 输出 `exp_home` / `exp_away` |
| **胜平负概率** | Dixon-Coles 泊松 + 平局 boost → 规则概率；再经校准、ML 修正、赔率融合、API 预测融合 | 输出 `prob_home_win` / `prob_draw` / `prob_away_win` |
| **比分** | 同一套 DC 模型，7×7 网格取 top_scores | 用于推荐比分与让球推导 |

调参与数据补充见 [模型命中率优化指南.md](模型命中率优化指南.md)、[可补充数据与模型提升.md](可补充数据与模型提升.md)。

## 二、期望进球层可改进点

### 1. 近期权重与样本选择（中收益、中难度）

- **现状**：`_weighted_avg` 对近期场次线性加权的「最近权重大」，权重形式固定。
- **可做**：
  - **指数衰减**：按「距今天数」或「场次倒序」做指数权（如 `decay^t`），更突出最近几场。
  - **按对手强度调整**：近期对手普遍强/弱时，对「场均进/失球」做简单对手修正（例如用联赛平均对手的期望失球做分母再标准化），避免「刚连碰强队」的队伍被低估。
- **落点**：`engine/predict.py` 中 `_weighted_avg`、`_team_recent_form_at_venue` / `_team_recent_form` 的调用与权重设计；若做对手强度需从赛程取对手 ID 再查其防守/进攻均值。

### 2. xG 使用方式（已优先真实 xG，可再微调）

- **现状**：优先 API 的 `expected_goals`，无则射正/总射门×系数；与形式期望进球按 `PREDICT_XG_BLEND` 混合。
- **可做**：
  - **按联赛或样本量调 blend**：数据多的联赛或近期场次多的队可略提高 xG 权重；样本少时降低 xG 权重或仅用形式期望。
  - **实际进球 − xG（把握/运气）**：近期「实际场均进球 − 近期场均 xG」若持续为正/负，可对期望进球做小幅加减（例如 0.05×差值），体现「近期把握能力」或回归预期；需防过拟合，建议权重很小并做 A/B 评估。
- **落点**：`config.py`（或 `predict_league_params.json`）的 `PREDICT_XG_BLEND`；若做「实际−xG」需在 `engine/predict.py` 中算近期实际与 xG 差再在 `exp_home`/`exp_away` 上加减。

### 3. 联赛与情境参数细化（高收益、低难度）

- **现状**：主场优势、疲劳系数、边界略偏主等有全局默认，部分可在 `predict_league_params.json` 按联赛覆盖。
- **可做**：
  - **联赛专属**：为低命中率联赛单独设 `PREDICT_HOME_ADVANTAGE`、`PREDICT_FATIGUE_FACTOR`、`PREDICT_BOUNDARY_HOME_NUDGE` 等（若尚未全部支持，可在 `_cfg(overrides, ...)` 中增加读取）。
  - **杯赛 vs 联赛**：若能从 `competition_id` 或赛事名区分杯赛，可对杯赛使用不同的 `last_n` 或主场系数（杯赛主场优势常更弱）。
- **落点**：`config.get_league_overrides()` 与 `engine/predict.py` 中所有 `_cfg(overrides, "PREDICT_*", default)`；`data/predict_league_params.json` 增加键。

## 三、胜平负与比分层可改进点

### 1. Dixon-Coles 参数按联赛拟合（中高收益、中难度）

- **现状**：`_dc_rho`（低比分相关性）、`_draw_boost_coef` 已支持联赛覆盖（`data/predict_league_params.json` 中可设 `PREDICT_DC_RHO`、`PREDICT_DRAW_BOOST_COEF`）；默认 rho=-0.13。
- **可做**：用历史比分数据按联赛拟合 rho（及平局 boost），写回 `predict_league_params.json`；拟合目标可为「历史平局率 / 1–1 占比」等。
- **落点**：可新增 `engine/dc_fit.py` 或脚本，读 matches 比分写回联赛参数。

### 2. 比分网格与高比分（低收益、低难度）

- **现状**：比分网格大小由 `PREDICT_MAX_GOALS` 控制，默认 8（即 8×8，每侧 0～7 球）；支持联赛覆盖。
- **可做**：高比分联赛可在 `predict_league_params.json` 中设 `PREDICT_MAX_GOALS`: 10 等。

### 3. 其他得分模型（进阶、可选）

- **Skellam**（主客进球差分布）：可用于「主胜/平/客胜」的另一种推导，与泊松体系互补。
- **Bivariate / 双变量泊松**：显式建模主客进球相关性，部分文献在平局预测上略优，实现与调参成本更高。
- 建议在 DC + 联赛拟合仍不够时再考虑，优先做参数拟合与数据特征。

## 四、数据与特征

### 1. 已文档化、可尽快接入或加强

- **xG**：已接入并优先真实 xG；确保竞彩/主库场次有 `api_football_statistics` 的近期数据并开启 `PREDICT_USE_XG`，见 [按优先级加特征与评估实操.md](按优先级加特征与评估实操.md)。
- **赛程密度 / 休息天数**：已参与疲劳系数；可再区分「连续客场」「一周多赛」等，在 `predict_match` 中增加轻量系数（如连续客场再乘 0.98）。
- **实际进球 − xG**：见第二节「xG 使用方式」。

### 2. 需新数据或新加工

- **裁判**：主裁判历史出牌/点球倾向 → 对平局或大比分敏感场次做微调。
- **动机（保级/争冠/欧战）**：轮次与积分差 → 对「战意」做 0/1 或连续标签，仅作轻量加权以免过拟合。
- **阵容/首发稳定性**：换帅、阵型、轮换比例 → 稳定性低时略降 `last_n` 权重或提高联赛收缩。
- **xGOT / SGA**：若有数据源，可作「终结能力」的微调特征，见 [参考Opta定义与指标.md](参考Opta定义与指标.md)。

以上在 [可补充数据与模型提升.md](可补充数据与模型提升.md) 中有更细说明与优先级。

## 五、校准与 ML 修正层

### 1. 校准（Platt 等）

- **现状**：支持全局与联赛专属校准参数。
- **可做**：按**时间段**（如每半赛季）重训校准，减少联赛风格随赛季的漂移；或对「高置信度子集」单独校准，使推荐区间概率更准。
- **落点**：`engine/calibration.py`、`calibrate-probs` 命令与 `calibration_params.json` 结构。

### 2. ML 修正层（outcome_ml）

- **现状**：以规则期望进球与规则概率等为特征，预测胜平负再与规则概率混合。
- **可做**：
  - **特征**：加入「主客排名差」「近期实际−xG」「伤停人数/关键球员」等（若尚未全部入特征），注意避免未来信息泄露。
  - **联赛/赛事**：已支持联赛专属模型时可扩大使用范围；或按「联赛类型」（五大联赛 / 次级 / 杯赛）分模型。
  - **正则与早停**：避免过拟合，用验证集早停或 L2；重训后务必用未参与训练的时间段做评估。
- **落点**：`engine/outcome_ml.py`、`train-outcome-ml` 命令；特征列表与模型保存路径。

## 六、产品与评估侧

- **高置信度子集**：仅对「推荐概率 ≥ 某阈值」的场次统计命中率，便于产品标注「高置信推荐」并单独优化该子集（调参、校准、ML 权重）。
- **按联赛/按玩法**：继续用 `predict-eval --by-competition`、`jc-predictions-eval` 的让球统计，对弱联赛或让球玩法单独调参或单独模型。
- **时间切分评估**：用「最近 N 个月」或「未参与训练/校准的月份」做 hold-out 评估，避免只看全量命中率掩盖过拟合或分布漂移。

## 七、建议实施顺序（简要）

1. **不动代码**：按 [模型命中率优化指南.md](模型命中率优化指南.md) 做联赛调参、重训校准与 ML、补赔率/xG 数据，并评估。
2. **期望进球**：联赛/情境参数细化、xG blend 按联赛或样本量微调；再考虑近期权重（指数衰减、对手强度）。
3. **胜平负/比分**：Dixon-Coles 的 rho（及平局 boost）按联赛拟合；必要时扩大比分网格。
4. **数据特征**：实际−xG、赛程密度细化（连续客场等）、裁判/动机等按数据到位情况逐步加。
5. **校准与 ML**：时间段/高置信度校准、ML 特征与联赛分模型、正则与早停。

每改一层都建议：**repredict 历史 → 同一评估口径对比**（全量 + 按联赛 + 高置信度），再决定是否保留或回滚。

## 八、Step 1 执行清单（不动代码，先跑一遍）

在改模型代码前，建议先执行以下命令完成调参、重训与评估，建立基线。

```bash
# 1) 按联赛看命中率，记下弱联赛
python3 main.py predict-eval --by-competition
python3 main.py suggest-improvements

# 2) 按需编辑 data/predict_league_params.json（last_n、PREDICT_DRAW_BOOST_COEF、PREDICT_HOME_ADVANTAGE 等）
# 3) 重训 ML 与校准（样本建议 2000+ 已完赛且有预测）
python3 main.py train-outcome-ml
python3 main.py calibrate-probs

# 4) 重新预测并评估
python3 main.py repredict-history --db-only
# 若用竞彩：python3 main.py repredict-all --years 2025,2026 或 refresh-and-eval
python3 main.py predict-eval
python3 main.py predict-eval --by-competition

# 5) 可选：补赔率与 xG 数据后再评估
# python3 main.py odds-api-by-db --limit 7
# python3 main.py statistics-api --date 2025-01-15   # 及竞彩相关场次的统计
# 再 repredict + predict-eval
```

## 九、本节已实现的改进（对应 Step 2～4）

以下已在代码/配置中落地，改完需 **repredict + predict-eval** 看效果。

| 项 | 说明 | 配置 / 联赛覆盖 |
|----|------|-----------------|
| **联赛参数细化** | 积分榜微调、边界略偏主、xG blend 支持按联赛覆盖 | `predict_league_params.json` 可设 `PREDICT_STANDINGS_NUDGE_FACTOR`、`PREDICT_BOUNDARY_HOME_SPREAD`、`PREDICT_BOUNDARY_HOME_NUDGE`、`PREDICT_XG_BLEND` |
| **近期形式指数衰减** | 近期场次权重大时可用指数衰减替代线性 | `PREDICT_FORM_WEIGHT_DECAY`（0=线性，0&lt;decay&lt;1 如 0.85=指数） |
| **比分网格 8×8** | 每侧 0～7 球，可调 | `PREDICT_MAX_GOALS` 默认 8，联赛可覆盖 |
| **实际−xG 微调** | 有 xG 时按近期（实际进球−xG）小幅加减期望 | `PREDICT_ACTUAL_XG_NUDGE_FACTOR`（默认 0.05）、`PREDICT_ACTUAL_XG_NUDGE_CAP`（默认 0.15），0=关闭 |
| **连续客场** | 客队最近 N 场均为客场时略降客队期望 | `PREDICT_CONSECUTIVE_AWAY_MIN`（默认 2）、`PREDICT_CONSECUTIVE_AWAY_FACTOR`（默认 0.98） |
| **DC 参数** | rho、平局 boost 已支持联赛覆盖 | `predict_league_params.json` 可设 `PREDICT_DC_RHO`、`PREDICT_DRAW_BOOST_COEF` |

## 十、竞彩/阵容相关可优化项（2024–2026 有实际首发后可做）

| 优化项 | 做法 | 命令/配置 |
|--------|------|-----------|
| **按联赛调伤停权重** | 预计缺 vs 实际关键缺若某联赛系统性低估更严重，可对该联赛单独提高 KEY_WEIGHT | `lineup-key-absent-analysis --years 2024,2025,2026 --by-league` 看主客均差；在 `data/predict_league_params.json` 为该联赛增加 `PREDICT_INJURY_KEY_PLAYER_WEIGHT`（如 3.5、4.0） |
| **概率校准 + ML 修正** | 用历史预测+赛果更新校准与 ML 模型，再评估 | `python3 main.py refresh-models`（calibrate-probs + train-outcome-ml），再 `refresh-and-eval` 或 `jc-predictions-eval` |
| **数据驱动推荐门槛** | 按「联赛×推荐类型×概率区间」历史命中率，低命中率细分改推胜/负 | `jc-predictions-eval --export-segment-stats data/jc_rec_segment_hit_rates.json`，配置 `JC_REC_USE_SEGMENT_STATS=true`、`JC_REC_SEGMENT_STATS_PATH`；或 `--export-league-rec-params` 生成联赛级 min_prob_70 |
| **提高预计缺阵覆盖** | 预计缺越准，key_count 越准，模型对伤停反应越合理 | 确保竞彩分析页/伤停文章解析完整；`JC_USE_PREDICTED_LINEUP_FOR_KEY_ABSENT=true` 让预计首发参与 key_count（已默认开启） |
