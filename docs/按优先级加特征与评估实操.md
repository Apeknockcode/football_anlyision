# 按优先级加特征/数据与评估实操

按 [竞彩预测命中率优化.md](竞彩预测命中率优化.md)#七、全量 70% 很难时如何对待 中的技术路线，本页给出**具体操作步骤**与**评估流程**。

---

## 执行清单（按顺序做）

在项目根目录下、已配置好 `.env`（含 `API_FOOTBALL_KEY`、`MONGO_URI` 等）的前提下，按下面顺序执行。

### 第一步：补数据

```bash
# 1. 补未来赛程（赛程密度特征用；matches 里要有 D+1～D+7 的场次）
python main.py ingest-api-upcoming --seasons 2025,2026

# 2. 补单场统计（xG 用；按「需要评估的预测所在日期」往前推，覆盖主客队近期 5 场）
#    示例：评估 2025 年则至少拉 2024-12 ～ 2025 年部分日期；可写脚本逐日拉或手动拉关键日期
python main.py statistics-api --date 2025-01-01
python main.py statistics-api --date 2025-01-08
python main.py statistics-api --date 2025-01-15
# … 按需继续更多日期（注意 API 限流，可加 --rate-limit 或间隔执行）
```

### 第二步：开启 xG / 赛程密度

在 `.env` 中增加或修改（赛程密度已有默认，可不改）：

```bash
PREDICT_USE_XG=true
PREDICT_XG_BLEND=0.3
# 赛程密度（可选，默认已开）
# PREDICT_FATIGUE_MATCHES_NEXT_7D=2
```

### 第三步：重写预测

```bash
# 主库历史预测重算（DB predictions + prediction_log）
python main.py repredict-history

# 若主要看竞彩口径，再按年/按日期重写 jc_predictions
python main.py predict-jc-from-self-improvement --year 2025 --include-finished
python main.py predict-jc-from-self-improvement --year 2026 --include-finished
```

### 第四步：评估

```bash
# 全量 + 按联赛
python main.py predict-eval
python main.py predict-eval --by-competition

# 竞彩口径（按年）
python main.py jc-predictions-eval --year 2025
python main.py jc-predictions-eval --year 2026
```

对比「开启 xG/赛程密度前」的命中率，看全量、按联赛、高置信度是否提升。若只做赛程密度、暂不开 xG，则第二步只保留默认（不设 `PREDICT_USE_XG`），仍按第三、四步重写并评估。

## 一、xG（预期进球，与 Opta 定义对齐）

- **xG 含义**：预期进球（Expected Goals）按行业/Opta 定义为「机会质量」加总——每脚射门有 0～1 的得分概率，单场/球队 xG 为所有射门概率之和。项目中优先使用 API 统计里的 `expected_goals` 字段，无则用射门/射正×系数作为代理。
- **展示区分**：仪表盘里 API 预测接口的进球数（如 `-2.5`/`-1.5`）展示为「**预测进球**」，与「xG（预期进球）」区分，避免与 Opta 机会质量 xG 混淆。
- **统计定义与扩展**：详见 [参考Opta定义与指标.md](参考Opta定义与指标.md)。

### 1. 数据准备

- **单场统计**来自 API-Football `fixtures/statistics`，需先按日期拉取并写入 `data/api_football_statistics.json`：
  ```bash
  # 按日期拉取（已完赛场次才有统计）
  python main.py statistics-api --date 2025-01-15
  # 或批量：对历史/当季重要日期逐日拉取（受 API 限流影响）
  ```
- **比赛与 fixture 对应**：预测用的比赛需有 `source_id=af_{fixture_id}`（来自 API-Football ingest），这样近期场次才能从 `api_football_statistics` 的 `by_fixture` 里找到统计并算近期场均 xG。

### 2. 开启 xG 混合

- 在 `.env` 中设置：
  ```bash
  PREDICT_USE_XG=true
  PREDICT_XG_BLEND=0.3
  ```
- 逻辑说明：主/客队各自取**近期 5 场**已完赛且在本库有 `source_id` 的比赛；统计中**优先使用 API 的 `expected_goals`**（与 Opta 一致），无则用「Shots on Goal」或「Total Shots」×系数换算成近似 xG 后，与规则期望进球按 `PREDICT_XG_BLEND` 混合。无统计数据时自动回退为不混 xG。

### 3. 评估是否提升

- 重写预测（含历史）再评估：
  ```bash
  python main.py repredict-history
  # 或竞彩：按年/按日期重写
  python main.py predict-jc-from-self-improvement --year 2025 --include-finished
  ```
- 看全量 + 按联赛 + 高置信度命中率：
  ```bash
  python main.py predict-eval
  python main.py predict-eval --by-competition
  python main.py jc-predictions-eval --year 2025
  ```
- 对比开启 xG 前后的 `outcome_accuracy`、`outcome_accuracy_high_conf` 及按联赛分布，决定是否保留或微调 `PREDICT_XG_BLEND`（如 0.2～0.4）。

## 二、赛程密度（已接入）

- **含义**：对当场比赛日 D，统计主/客队在 **D+1 ～ D+7** 天内的比赛场次数；若某队在该区间内比赛数 ≥ 2（默认），则对该队施加与「休息不足」相同的疲劳系数（`PREDICT_FATIGUE_FACTOR`），降低其期望进球。
- **配置**（可选，均有默认）：
  ```bash
  PREDICT_FATIGUE_DAYS_THRESHOLD=3
  PREDICT_FATIGUE_FACTOR=0.95
  PREDICT_FATIGUE_MATCHES_NEXT_7D=2
  ```
- **数据依赖**：`matches` 表中需包含**未来赛程**（未开赛也可），否则「未来 7 天内场次」为 0。若仅 ingest 已完赛，需先跑 `ingest-api-upcoming` 或等价命令把未来场次写入。
- **评估**：与 xG 相同——重写预测后跑 `predict-eval` / `jc-predictions-eval`，看全量及头部联赛命中率是否稳定或提升。

---

## 三、单场统计聚合（射门、控球等，后续可选）

- **现状**：`api_football_statistics.json` 已有单场射门/控球等，当前仅用于 xG 代理（射门/射正）与复盘展示。
- **可扩展**：按球队聚合「近期场均射门、控球率、角球」等，作为 ML 修正层或规则侧轻量特征（如「控球高且射门多」略升期望进球）。需在 `engine/outcome_ml.py` 或规则侧增加特征与训练/入参，工作量相对较大，建议在 xG + 赛程密度稳定后再做。
- **评估**：加特征后重训 `train-outcome-ml`、必要时 `calibrate-probs`，再重写预测并跑上述评估命令。

## 四、推荐执行顺序与命令汇总

| 步骤 | 动作 | 命令示例 |
|------|------|----------|
| 1 | 补未来赛程（赛程密度用） | `python main.py ingest-api-upcoming --seasons 2025,2026` |
| 2 | 补单场统计（xG 用，按需按日拉） | `python main.py statistics-api --date YYYY-MM-DD` 逐日拉取并写入 `data/api_football_statistics.json` |
| 3 | 开启 xG | `.env`: `PREDICT_USE_XG=true`, `PREDICT_XG_BLEND=0.3` |
| 4 | 重写预测 | **主库**：`repredict-history`（只更新主库 `predictions`，约 4702 场）。**竞彩**：`predict-jc-from-self-improvement --year 2025 --include-finished`（更新 `jc_predictions`）。**一次更新两处**：`python main.py repredict-all --years 2025,2026` |
| 5 | 评估全量/按联赛/高置信度 | `predict-eval`, `predict-eval --by-competition`, `jc-predictions-eval --year 2025` |
| 6 | 重训 ML/校准（样本足够时） | `python main.py train-outcome-ml`，`python main.py calibrate-probs`，再重复 4～5 |

每次只改一两项（例如先只开 xG，或只补赛程密度），便于归因「全量是否缓慢上移」。

**说明**：`repredict-history` 只针对**主库**（football 库的 `matches` + `predictions`），数量 4702 是主库已完赛且有预测的场次。竞彩预测在**另一库**（self_improvement_football 的 `jc_predictions`），数据来自 `jingcai_match_analysis`，需单独用 `predict-jc-from-self-improvement` 更新。调参后若希望主库和竞彩都用新参数，可运行 **`repredict-all`** 一次完成两边的重算。

## 五、拉取统计命令说明

- 使用现有命令：`python main.py statistics-api --date YYYY-MM-DD`（不传 `--date` 则用当天）。
- 会调用 `etl.api_football_statistics.fetch_and_save_statistics_for_date`，按日拉取五大联赛该日 fixture 的统计并合并进 `data/api_football_statistics.json`。历史日期需逐日调用并注意 API 限流。拉取足够覆盖「主客队近期 5 场」的日期后，再开启 `PREDICT_USE_XG` 并重写预测、按上表评估。
