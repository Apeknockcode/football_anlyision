# 关键球员与缺阵分析设计

在 `match_lineups` 已有赛后实际阵容（主客队首发人数、首发/替补名单）的前提下，本文档说明如何做**关键球员**与**缺阵**相关分析，用于复盘和后续调参。

---

## 1. 分析目标

| 分析项 | 说明 | 用途 |
|--------|------|------|
| **关键球员 vs 实际首发** | 体彩「关键球员」（射手/重点球员）中有几人**实际首发**、几人**未首发** | 复盘：预测时用的 `home_absent_key_count` 与赛后真实是否一致；评估伤停/预计首发逻辑 |
| **预测缺阵 vs 实际缺阵** | 预测阶段给出的「关键球员缺阵人数」与「关键球员中未在实际首发的人数」对比 | 调参：若预测高估/低估缺阵，可调整 KEY_WEIGHT 或预计首发参与方式 |
| **伤停名单 vs 实际首发** | 伤停里标记缺阵的人，赛后是否真的未首发（或反而首发了） | 验证伤停数据质量、滞后性 |

---

## 2. 数据来源

| 数据 | 来源 | 用途 |
|------|------|------|
| **关键球员名单** | `jingcai_match_analysis.match_player`（主客 `home`/`away` 下的 playerList/scorerList） | 与「实际首发名单」对比，算实际首发/未首发人数 |
| **伤停缺阵名单** | 同文档 `injury_suspension` 解析 → `home_absent` / `away_absent` | 与关键球员结合得 `home_absent_key_count`；亦可与实际首发对比验证 |
| **实际首发名单** | `self_improvement_football.match_lineups`：`home_starting` / `away_starting`（每项含 `player_name` 等） | 裁判：谁真的首发了 |

姓名需做**规范化**再匹配（如去空格、小写、统一别名），与现有 `parse_jingcai_analysis_for_predict` 中的 `_norm_name_for_key` 一致。

---

## 3. 实现思路

### 3.1 单场「关键球员 vs 实际首发」

对每场已完赛且同时具备以下条件的比赛：

- 有 `jingcai_match_analysis` 且含 `match_player`（关键球员名单）
- 有 `match_lineups` 且含 `home_starting` / `away_starting`（非仅 count）

步骤：

1. 从分析文档解析出主客队**关键球员规范化姓名集合**（与 parse 中逻辑一致）。
2. 从 `match_lineups` 取出主客队**实际首发**的规范化姓名集合（从 `home_starting`/`away_starting` 的 `player_name` 或等效字段提取）。
3. 计算：
   - **关键球员中实际首发人数**：`key_started = key_names ∩ actual_starting`
   - **关键球员中实际未首发人数**：`key_absent_actual = key_names - actual_starting`（即「实际缺阵」）
4. 与预测阶段的 `home_absent_key_count` / `away_absent_key_count` 对比：
   - 若 `pred_key_absent ≈ key_absent_actual`，说明预测时的关键球员缺阵估计较准；
   - 若系统性偏大/偏小，可考虑调整 KEY_WEIGHT 或是否启用「预计首发」参与 key_count。

### 3.2 伤停 vs 实际首发（可选）

- 对伤停中的每条缺阵人员，在对应队实际首发名单中查找（规范化后）：
  - 未出现在首发 → 视为伤停「命中」；
  - 出现在首发 → 可能复出或伤停滞后，可记一笔用于质量统计。

### 3.3 与现有复盘的衔接

- **lineup_comparison_report** 当前已有：`pred_home_key_absent`、`pred_away_key_absent`、`actual_home_starting_count`、`actual_away_starting_count`。
- 扩展方式：
  - 在同一报告中增加字段：**实际关键球员首发数**、**实际关键球员未首发数**（及可选「伤停命中/漏报」），便于同屏对比。
  - 或单独提供 `key_player_absence_analysis(date_from, date_to)`，返回每场的上述明细，再在复盘/仪表盘中按需展示或导出。

---

## 4. 输出与使用

### 4.1 建议输出字段（每场）

| 字段 | 说明 |
|------|------|
| sporttery_match_id, jc_date, home_cn, away_cn, league | 场次标识 |
| pred_home_key_absent, pred_away_key_absent | 预测时使用的关键球员缺阵人数（已有） |
| actual_home_key_starting, actual_away_key_starting | 关键球员中实际首发人数 |
| actual_home_key_absent, actual_away_key_absent | 关键球员中实际未首发人数 |
| actual_home_starting_count, actual_away_starting_count | 全队实际首发人数（已有） |

可选：

- `home_key_absent_names`, `away_key_absent_names`：实际未首发的关键球员姓名列表，便于人工抽查。

### 4.2 聚合统计（可选）

- 按日期/联赛：预测 key_absent 与实际 key_absent 的偏差（均值、分布）；
- 有阵容场次中「关键球员实际缺阵」与「该场结果/盘口命中」的交叉，用于评估关键球员缺阵对命中率的影响。

---

## 5. 落库与接口

- **是否落表**：若需按场次快速查询或做日报，可新增集合/表（如 `key_absence_review`）存每场的关键球员实际首发/缺阵结果；否则仅用函数按需计算、导出或 API 返回即可。
- **接口**：现有 `lineup-comparison` CLI 与 `/api/jc-today/lineup-comparison` 可在返回中增加上述字段；或新增 `key-absence-analysis` 与对应 API，专门返回关键球员缺阵明细。

---

## 6. 小结

- **关键球员**来自 `jingcai_match_analysis.match_player`，**实际首发**来自 `match_lineups.home_starting` / `away_starting`，通过姓名规范化做集合运算得到「关键球员实际首发/未首发」人数。
- **预测缺阵**（`home_absent_key_count` / `away_absent_key_count`）与**实际缺阵**对比，用于复盘与 KEY_WEIGHT / 预计首发逻辑的调优。
- 在现有 `lineup_comparison_report` 上扩展字段，或单独提供 `key_player_absence_analysis`，再通过 CLI/API 暴露即可；是否落库视查询与报表需求而定。
