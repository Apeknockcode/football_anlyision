# 基于现有数据提高竞彩预测命中率

本文档说明如何利用 **self_improvement_football** 与 **jingcai_match_analysis** 中已有数据，让模型在竞彩预测时提高胜平负命中率。

---

## 一、现有数据与当前使用情况

### 1. self_improvement_football 中已有数据

| 集合/数据 | 内容 | 当前是否参与竞彩预测 |
|-----------|------|------------------------|
| **api_football_statistics** | 单场统计（射门、控球、角球等，按 fixture_id） | 否：预测时未按主客队近期场次聚合后传入 |
| **jc_predictions** | 模型预测结果（写回用） | 是（输出） |
| **jingcai_teams** | 竞彩队名 ↔ 英文名 | 是（队名解析） |

### 2. jingcai_match_analysis 中已有数据

| 字段 | 来源接口 | 内容 | 当前是否参与竞彩预测 |
|------|----------|------|------------------------|
| **match_head** | getMatchHeadV1 | 对阵头部、排名、主客场成绩 | 否（仅展示） |
| **injury_suspension** | getInjurySuspensionV1 | 主客队伤停名单 | 否 |
| **match_player** | getMatchPlayerV1 | 射手信息（近 N 名） | 否 |
| **result_history_all / same_tournament** | getResultHistoryV1 | 历史交锋 | 否（主库 matches 的 H2H 在用） |
| **match_feature** | getMatchFeatureV1 | 近 N 场、场均进/失球等特征 | 否 |
| **future_matches** | getFutureMatchesV1 | 未来赛事 | 否 |
| **odds** | getFixedBonusV1 | 体彩固定奖金（胜平负、让球） | 否 |

**结论**：竞彩批量预测（`predict-jc-from-self-improvement`）目前只从 jingcai_match_analysis 读取**场次列表**（主客队、联赛、日期），然后调用 `predict_match(..., match_date=date_only)`，**没有传入赔率、伤停、未来场次**等，因此这些数据尚未参与模型计算。

---

## 二、模型已支持但竞彩预测未传入的输入

`engine/predict.py` 中 `predict_match` 已支持以下可选参数，竞彩预测时未传则相当于未用：

| 参数 | 作用 | 数据来源建议 |
|------|------|--------------|
| **odds** | 与模型概率线性融合，提升稳定性 | jingcai_match_analysis.odds（体彩固定奖金） |
| **home_absent / away_absent** | 缺阵名单 → 期望进球下调、关键球员数 | jingcai_match_analysis.injury_suspension 解析 |
| **home_matches_next_7d / away_matches_next_7d** | 未来 7 天比赛数 → 赛程密度/疲劳 | jingcai_match_analysis.future_matches 解析 |
| **home_rank / away_rank** | 积分榜排名微调 | 主库 league_standings 或 match_head 排名 |
| **xg_home / xg_away** | xG 混合（若开启 PREDICT_USE_XG） | api_football_statistics 按主客队近期场次聚合 |

## 三、提高命中率的具体做法

### 3.1 优先：竞彩预测时接入 jingcai 赔率、伤停、未来场次（必做）

- **赔率**：列表接口已返回每场的 `odds`（体彩 getFixedBonusV1），在 `run_predict_jc_from_self_improvement` 中把 `m.get("odds")` 转为 `predict_match` 所需的 `spf_win/spf_draw/spf_loss` 格式并传入，即可启用**赔率与模型概率融合**。
- **伤停**：对每场用 `jc_match_analysis_load(sporttery_match_id)` 取完整文档，从 `injury_suspension` 解析出 `home_absent`、`away_absent`（与现有 injury_db 格式一致），传入 `predict_match`，模型会对缺阵与关键球员做期望进球下调。
- **未来场次**：从同一文档的 `future_matches` 解析主客队未来 7 天内比赛场次，传入 `home_matches_next_7d`、`away_matches_next_7d`，与现有「休息天数」一起参与赛程密度/疲劳系数。

实现要点：

- 在 `main.run_predict_jc_from_self_improvement` 中，对每场在解析完 home_id/away_id 后：
  - 若列表项已有 `odds` 且含胜平负，直接传入 `predict_match(..., odds=...)`；
  - 调用 `jc_match_analysis_load(m["match_id"])` 取分析文档，用统一解析函数得到 `home_absent`、`away_absent`、`home_matches_next_7d`、`away_matches_next_7d`，再传入 `predict_match`。
- 体彩 `injury_suspension` 的 value 结构需解析为与 `match_injury` 一致的 `home_absent`/`away_absent` 列表（如 `[{"name": "...", "reason": "..."}]`），若结构不同可写适配层。

这样**不改变模型公式**，仅把已有数据灌入现有参数，即可提升命中率（尤其是赔率融合与伤停下调）。

### 3.2 单场统计（api_football_statistics）的用法

- **用途**：主/客队「近期已完赛」场次的射门、控球等聚合 → 作为风格/压制力或 xG 近似，参与期望进球或概率微调。
- **做法**：
  - 竞彩场次若有 `api_football_fixture_id`，预测时取主客队在主库中的**近期比赛**（与现有 `predict_team_recent_matches_with_source` 一致），若这些比赛有 `api_football_statistics` 中的 fixture_id，则从库中读出统计并聚合（如近期场均射门、射正、控球率）。
  - 将聚合结果转为 `predict_match` 的 `xg_home`/`xg_away`（或后续扩展的「近期场均射门/控球」等参数），在开启 `PREDICT_USE_XG` 时参与计算。
- **注意**：单场统计针对**已完赛**场次，当前场是未来场时，只能用于「主客队近期表现」的增强，不能用于当前场本身。

### 3.3 历史交锋、射手、match_feature（可选增强）

- **历史交锋**：主库已用 matches 的 H2H；jingcai 的 `result_history_*` 可与主库 H2H 互为补充（例如主库缺场时用体彩同主客、同赛制结果做权重或回退）。
- **射手信息（match_player）**：可用来识别「关键球员是否在伤停名单」，从而更准地算 `home_absent_key_count`/`away_absent_key_count`，或仅作展示。
- **match_feature**：体彩已算好的近 N 场、场均进/失球等，可作为展示或与主库近期/H2H 融合时的先验权重，不改变核心公式即可小幅提升一致性。

---

## 四、建议实施顺序

1. **第一步（必做）**：在 `run_predict_jc_from_self_improvement` 中接入 **赔率 + 伤停 + 未来场次**，并传入 `predict_match`。  
   - 完成后重跑：`predict-jc-from-self-improvement --year 2025 --include-finished`，再 `jc-predictions-eval --year 2025` 对比命中率。
2. **第二步**：在预测链路中按主客队近期场次聚合 **api_football_statistics**，得到 xG 近似或射门/控球特征，传入 `predict_match`（需 PREDICT_USE_XG 或新参数）。  
   - 评估对 MAE / 胜平负命中率的影响后再决定是否默认开启。
3. **第三步**：视需求再接入历史交锋补充、射手关键球员、match_feature 权重等。

---

## 五、小结

- **现状**：jingcai_match_analysis 的伤停、赔率、未来场次、单场统计等**尚未参与**竞彩预测计算；模型已支持这些输入，只是竞彩分支未传。
- **最有效且易落地**：在竞彩预测流程中按场读取 jingcai 分析文档，解析**赔率、伤停、未来场次**并传入 `predict_match`，即可在不改模型结构的前提下提高命中率。
- **进一步**：将 api_football_statistics 按主客队近期场次聚合后传入，可增强 xG/风格特征，再配合联赛调参、ML 修正与校准，持续逼近「高置信度 70%+」或全量提升。
