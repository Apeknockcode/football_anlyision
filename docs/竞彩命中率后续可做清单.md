# 竞彩命中率：调整完后还需做的、仍不满足时可做

当前全量胜平负约 **50.5%**。若仍不满足，可按下面清单逐项做（按**性价比/可执行性**排序）。

---

## 一、已做过的（当前状态）

- 按联赛调参：`data/predict_league_params.json`（last_n、PREDICT_ODDS_FUSION_WEIGHT_MODEL 等）
- 全局默认模型权重：`config.PREDICT_ODDS_FUSION_WEIGHT_MODEL = 0.50`
- 按联赛校准：`calibrate-probs --by-competition`，结果在 `data/calibration_params.json`
- 低命中率联赛单独微调：英冠、美职、日职、日乙、韩职、澳超、法乙、德乙（更偏赔率 + 部分 last_n 缩短）

---

## 二、立即可做（不改数据源）

### 1. 重训 ML 修正层（含联赛专属）

当前已开启 `PREDICT_USE_OUTCOME_ML=true`，ML 层在规则+赔率+校准之后做一次修正。重训可吃掉新数据、可能抬一点全量。

```bash
# 全量重训（主库 + 竞彩样本）
python3 main.py train-outcome-ml

# 对样本多的低命中率联赛单独训（如英冠、美职、日职等），预测时自动用该联赛模型
# 先查 competition_id：竞彩侧联赛名对应 self_improvement 里的 competition_id
python3 main.py train-outcome-ml --competition-id <联赛ID>
```

多试几个随机种子，选命中率最高的：

```bash
PREDICT_OUTCOME_ML_RANDOM_STATE=42 python3 main.py train-outcome-ml
PREDICT_OUTCOME_ML_RANDOM_STATE=99 python3 main.py train-outcome-ml
```

然后：

```bash
python3 main.py repredict-all
python3 main.py jc-predictions-eval --all-time
```

### 2. 调 ML 修正层权重

`config.py` 或环境变量：`PREDICT_OUTCOME_ML_WEIGHT`（默认约 0.3～0.4）。  
若 ML 训练集准确率明显高于规则，可略提高到 0.35～0.45；若担心过拟合，可降到 0.25。改完同样要 `repredict-all` 再 `jc-predictions-eval`。

### 3. 对「校准后反而变差」的联赛关闭校准

若某联赛校准时样本少或分布偏，校准后命中率下降，可在代码里对该联赛 **跳过校准**（仍用规则+赔率+ML，不用 Platt 缩放）。  
需要改 `engine/calibration.py` 的 `apply_calibration`：当 `competition_id` 在「禁用校准列表」时直接返回原概率。列表可先设为：低命中率且样本一般的联赛 ID，再根据 `jc-predictions-eval` 按联赛结果微调。

### 4. 继续微调联赛参数（小步）

对仍明显偏低的联赛，在 `data/predict_league_params.json` 里：

- 再降一点 `PREDICT_ODDS_FUSION_WEIGHT_MODEL`（更偏赔率），或
- 微调 `last_n`（8/10/12）、`PREDICT_DRAW_BOOST_COEF`、`PREDICT_HOME_ADVANTAGE`

每次只改 1～2 个联赛、步长要小，然后 `repredict-all` → `jc-predictions-eval --all-time`，看全量及该联赛变化。

## 三、补数据后再评估（中期）

| 动作 | 作用 | 命令/参考 |
|------|------|------------|
| **赔率覆盖** | 有赔率才做模型+赔率融合，通常更稳 | 按日积累体彩/竞彩赔率；`sporttery-odds-to-db`、`jc-odds-to-db`；见 [可补充数据与模型提升.md](可补充数据与模型提升.md) |
| **积分榜/排名** | 排名微调 + ML 的 rank_diff 特征 | `standings-api` 或 `standings-backfill`，再 `train-outcome-ml` |
| **xG/统计** | 与形式期望进球混合，减弱偶然大比分干扰 | `PREDICT_USE_XG=true`、`PREDICT_XG_BLEND=0.3`，并跑 `statistics-api` 等补统计 |
| **更多历史赛季** | 近期场次与 H2H 更足，期望进球更稳 | `ingest-api-history` 等按需扩展 |

补完一批数据后建议：`refresh-models`（或至少 `calibrate-probs --by-competition` + `train-outcome-ml`）→ `repredict-all` → `jc-predictions-eval --all-time`。

## 四、产品/策略侧（不提高模型，但提高「看到的」命中率）

- **主推高置信度**：只展示或主推「推荐概率≥55%」或「≥60%」的场次，这类子集命中率已在 70%+；全量 50.5% 作为背景即可。  
- **按联赛过滤**：弱联赛（如部分亚洲联赛、次级联赛）不主推或标为「参考」，重点推英超、德甲、荷甲、西甲、意甲等当前命中率较高的联赛。  
- **口径说明**：对外可说「高置信场次命中率约 70%」，避免用「全量 50%」当主口径。  

详见 [产品与评估策略.md](产品与评估策略.md)。

## 五、中长期：特征与模型升级

若希望从根上再抬 1～2 个点，需要加特征或改结构，例如：

- **ML 特征扩展**：除现有期望进球、概率、last_n、competition_id、rank_diff 外，加入近期胜率、近期实际进球 vs xG、赛程密度等（需在训练与预测管线里一致接入）。  
- **期望进球层改进**：主客/H2H 权重、时间衰减、主客分开 last_n 等，见 [模型改进方向.md](模型改进方向.md)。  
- **更多数据**：裁判、伤停细化、阵容/首发稳定性等，见 [可补充数据与模型提升.md](可补充数据与模型提升.md)。  

---

## 六、建议的迭代节奏

1. **每次只动一两项**，便于归因（例如先只重训 ML，或只关一个联赛的校准）。  
2. **固定评估口径**：始终用 `python3 main.py jc-predictions-eval --all-time` 看全量 + 按联赛，必要时截取最近 1 年再对比。  
3. **记录**：在表格或文档里记「改了什么 → 全量/某联赛命中率前后」，方便回溯。  
4. **定期刷新**：每积累一批新完赛或新赔率/积分榜后，跑一次 `calibrate-probs --by-competition`、`train-outcome-ml`、`repredict-all`，再评估。

---

## 七、总结：仍不满足时优先做哪几件

| 优先级 | 做什么 | 预期 |
|--------|--------|------|
| 1 | 重训 ML 修正层（含联赛专属 train-outcome-ml --competition-id） | 全量可能 +0.2%～0.5% |
| 2 | 调 PREDICT_OUTCOME_ML_WEIGHT、对明显「校坏」的联赛关校准 | 稳或小幅提升 |
| 3 | 补赔率 + 积分榜，再 refresh-models + repredict + eval | 更稳、有机会再抬一点 |
| 4 | 主推高置信 + 强联赛，弱联赛标参考 | 用户看到的命中率明显提高 |
| 5 | 加特征、改期望进球/模型结构 | 中长期才有明显提升 |

以上都做完仍不满足时，就需要在**数据**（更多/更准的赔率、xG、伤停、阵容等）和**模型结构**（期望进球公式、ML 特征与网络）上做更大投入，参见 [模型改进方向.md](模型改进方向.md) 与 [可补充数据与模型提升.md](可补充数据与模型提升.md)。
