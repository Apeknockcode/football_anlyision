# 项目结构：数据来源、数据依赖与数据库

本文档说明本项目的目录布局、**数据来源**、**数据依赖**与**数据库**的对应关系，便于维护与扩展。

- **数据库**：全权使用 **MongoDB**，业务数据不落 SQLite。
- **数据来源**：均采用 **API-Football**（api-sports.io）**付费档**。

## 二、数据来源（Data Sources）

**本项目数据来源均采用 API-Football（api-sports.io），使用付费档。** 赛程/赛果、赔率、积分榜、伤停、预测接口等均由 API-Football 拉取并写入 MongoDB。

| 数据来源 | 说明 | ETL 模块 | 写入位置 | 配置/依赖 |
|----------|------|----------|----------|-----------|
| **API-Football（付费档）** | 五大联赛赛程/赛果、赔率、积分榜、伤停、预测接口 | `etl/api_football_*.py`, `etl/injury_api_football.py` | 见下表 | `API_FOOTBALL_KEY(S)`, `API_FOOTBALL_BASE` |

### API-Football 写入明细

| 子模块 | 写入表/文件 | 用途 |
|--------|-------------|------|
| `api_football_match_ingest` | `matches`（五大联赛历史） | 赛程与赛果 |
| `api_football_odds` | `match_odds` | 胜平负赔率，供预测融合 |
| `api_football_standings` | `league_standings` | 积分榜，供预测排名特征、回填 matches.home_rank/away_rank |
| `api_football_predictions` | 不落表 | 预测接口结果与模型概率融合 |
| `api_football_statistics` | `data/api_football_statistics.json` | 单场统计（射门、控球等），可选 xG 近似 |
| `injury_api_football` | `data/injury_suspension.json` + `match_injury` | 伤停名单 |

## 三、数据依赖（Data Dependencies）

- **谁依赖谁**：下游依赖上游表/文件；上游更新后，下游需重算或重新拉取时才有新数据。

```
┌─────────────────────────────────────────────────────────────────────────────┐
│ 数据源（外部）                                                                │
│   API-Football（付费档）                                                      │
└─────────────────────────────────────────────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│ 入库层（MongoDB）                                                             │
│   competitions, seasons, teams, matches, events                              │
│   match_odds, league_standings, match_injury                                │
│   data/*.json（injury_suspension, api_football_*.json 等缓存/配置）            │
└─────────────────────────────────────────────────────────────────────────────┘
         │
         ├── 预测引擎 (engine/predict.py)
         │      依赖：matches, teams, competitions, match_odds, league_standings,
         │            match_injury, (可选) api_football_predictions
         │      写出：predictions, prediction_log
         │
         ├── 报告 (report/, engine/report_payload.py)
         │      依赖：matches, events, teams
         │      写出：data/reports/*.md, *.html
         │
         ├── 复盘 / 评估 (engine/prediction_log.py, engine/calibration.py)
         │      依赖：matches, prediction_log, predictions
         │
         └── API 与仪表盘 (api/app.py)
                依赖：上述全部（按接口读 matches / prediction_log / match_odds / match_injury / reports）
```

### 关键依赖简表

| 功能 | 依赖的表/数据 | 写出/更新 |
|------|----------------|-----------|
| 比分预测 | matches, teams, competitions, match_odds, league_standings, match_injury | predictions, prediction_log |
| 赔率融合 | match_odds（按场次） | — |
| 积分榜排名特征 | league_standings | matches.home_rank, away_rank（需 backfill） |

## 四、数据库（Database）

### 4.1 存储选择

**数据库全权使用 MongoDB。** 所有业务数据读写经 `db/repo.py` 走 MongoDB，表名对应为集合名。需配置 `MONGO_URI` 与 `USE_MONGO=true`。

业务代码**只通过 `db/repo.py`** 访问数据，不直接使用 `etl/schema.get_engine()` 或 MongoDB 连接（除 repo 内部）。

### 4.2 表/集合与用途

| 表/集合名 | 用途 | 主要写入方 |
|-----------|------|------------|
| `competitions` | 赛事 | api_football_match_ingest |
| `seasons` | 赛季 | 同上 |
| `teams` | 队伍（含 name_zh） | 同上 + 队名规范化脚本 |
| `matches` | 比赛（比分、raw_meta、主客排名等） | api_football_match_ingest、backfill 排名 |
| `events` | 事件（若有其他源导入） | 可选 |
| `predictions` | 单场预测（期望进球、胜平负概率） | engine/predict.save_prediction |
| `prediction_log` | 预测日志（含实际比分、复盘用） | 预测流程、auto-accumulate-log |
| `match_odds` | 单场赔率（胜平负等） | api_football_odds |
| `league_standings` | 积分榜 | api_football_standings |
| `match_injury` | 伤停 | injury_api_football, injury_db |

### 4.3 同步与迁移

- 数据全在 MongoDB，无需 SQLite→Mongo 或 RDS 迁移。若需备份/恢复，直接使用 MongoDB 的备份与恢复工具。

## 五、常用命令与数据流

| 目的 | 命令 | 涉及数据源/表 |
|------|------|----------------|
| 拉取历史赛程/赛果（API-Football） | `python main.py ingest-api-football` | API-Football → matches（MongoDB） |
| 补赔率 | `python main.py backfill-odds --date YYYY-MM-DD` 或 periodic 脚本 | API-Football → match_odds |
| 补积分榜 | `python main.py backfill-standings` | API-Football → league_standings |
| 伤停 | `python main.py injury-api --date YYYY-MM-DD` | API-Football → match_injury |
| 今日竞彩预测 | `python main.py daily-jingcai` 或 API `POST /predictions/run` | 读 matches + 写 prediction_log |
| 复盘统计 | `python main.py prediction-log recap` 或 API `/recap-stats` | prediction_log, matches |

## 六、清空 MongoDB 并重新拉取

需要**清空数据库、重新拉取并重新定义**时，按以下顺序执行：

1. **清空当前 MongoDB 库**（删除所有项目集合）  
   ```bash
   python main.py mongo-clear
   ```  
   需已配置 `MONGO_URI` 且 `USE_MONGO=true`。会清空：competitions, seasons, teams, matches, events, predictions, prediction_log, match_odds, league_standings, match_injury。

2. **重新拉取数据**（按需执行）  
   - 五大联赛历史赛程/赛果：`python main.py ingest-api-football --seasons 2023,2024,2025,2026`  
   - 补赔率：`python main.py backfill-odds --date YYYY-MM-DD` 或按日期范围多次执行  
   - 补积分榜：`python main.py backfill-standings`  
   - 伤停：`python main.py injury-api --date YYYY-MM-DD`（或按需日期）

3. **可选**：队名规范化、赔率与 matches 关联等  
   - `python main.py normalize-team-names`  
   - `python main.py link-match-odds`

## 七、通过 API 获取五大联赛数据并写入 MongoDB

通过 API-Football（付费档）拉取**历史比赛**，再按比赛补全**伤停、积分榜、赔率、亚赔**，全部写入 MongoDB。推荐顺序如下。

### 1. 历史比赛（先有场次）

拉取指定赛季五大联赛已完赛场次，直接写入 MongoDB（`USE_MONGO=true` 时）：

```bash
python main.py ingest-api-football --seasons 2023,2024,2025,2026
```

- 写入集合：`competitions`, `seasons`, `teams`, `matches`
- 可选 `--reset`：重拉前先删除这些赛季的已有比赛及关联数据

### 2. 伤停

按比赛日拉取伤停名单，写入 `match_injury`：

```bash
# 按日期
python main.py injury-api --date 2025-02-20 --merge

# 按 DB 中已有比赛日批量拉取（只拉 DB 里已有比赛的日期）
python main.py injury-api-by-db
```

### 3. 积分榜

按赛季拉取五大联赛积分榜，写入 `league_standings`，并可为每场比赛回填主客队当季排名（`home_rank` / `away_rank`）：

```bash
# 拉取指定赛季积分榜
python main.py standings-api --season 2025

# 按 DB 中比赛所在赛季拉取积分榜并回填每场排名
python main.py standings-backfill --seasons 2023,2024,2025
```

### 4. 历史交锋（Head-to-Head）

按 DB 中「主客对」拉取 API-Football 历史交锋并写入 `matches`，补全后仪表盘「历史交锋」与模型 `predict_head_to_head` 会有更多数据（仅处理 team_id 来自 API-Football ≥90000 的对）：

```bash
# 按 2024、2025 年比赛出现的主客对拉取 H2H 并写入 matches
python main.py h2h-backfill --years 2024,2025

# 只拉 20 组主客对（每组 1 次 API）；默认已有 ≥6 场的主客对会跳过，省次数且便于断点续跑
python main.py h2h-backfill --years 2024,2025 --limit 20 --dry-run   # 先看列表与将跳过的组
python main.py h2h-backfill --years 2024,2025 --limit 20

# 次数用完后改天再跑：同一命令即可，已够 6 场的主客对会自动跳过，只补不足的
python main.py h2h-backfill --years 2024,2025
```

### 5. 赔率与亚赔

按日期或按 DB 场次拉取**胜平负赔率**，并解析 **亚洲让球（亚赔）**（API 有则写入）：

```bash
# 按日期拉取（胜平负 + 亚赔若有）
python main.py odds-api --date 2025-02-20 --merge

# 按 DB 中比赛日批量补赔率（以 DB 为基准，只拉 DB 有的场次）
python main.py odds-api-by-db --years 2024,2025
```

- 写入集合：`match_odds`
- 字段：`spf_win` / `spf_draw` / `spf_loss`（胜平负）；若有亚赔则还有 `ah_handicap`、`ah_home`、`ah_away`

### 6. 可选后续

- **队名统一**：`python main.py normalize-team-names`（将 match_odds、match_injury 的主客队名规范为 teams 表队名）
- **赔率关联比赛**：`python main.py link-match-odds`（为 match_odds 回填 match_id，便于按场次查赔率）

以上与「数据来源」「数据依赖」「数据库」的对应关系，以本文档为准；代码细节以仓库内实现为准。
