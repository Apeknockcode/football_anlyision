# 竞彩命中率提升与对比流程

按「先联赛门槛+高置信门槛 → 再按联赛校准 → 再伤停微调 → 再单场推荐提升」执行，每次调整后均做对比。**每次只改一项并做对比**，命中率不升就回退。

---

## 一、执行顺序与结果摘要

| 步骤 | 操作 | 对比结论 |
|------|------|----------|
| **Step 0** | 导出当前 2026 基线 → `data/jc_eval_baseline.json` | 作为后续 before 基准 |
| **Step 1** | 联赛门槛 + 高置信门槛：生成 `jc_league_rec_params.json`，`JC_REC_HIGH_CONFIDENCE_MIN_PROB=0.68` | 不改变模型预测，仅展示/统计口径；今日推荐将按联赛 min_prob_70 过滤 |
| **Step 2** | 按联赛校准：`calibrate-probs --by-competition --train-date-from 2021-01-01 --train-date-to 2025-12-31`，重跑 2026 预测 | **提升**：胜平负 +1.3%，单场推荐 +2.6% |
| **Step 3** | 伤停微调：`lineup-key-absent-analysis` → `merge-injury-params`，重跑 2026 预测 | **持平**：与 Step 2 后指标一致，保留伤停权重 |
| **Step 4** | ML 权重 0.4 → 0.45，重跑 2026 预测 | **已采用**，单场推荐约 +0.3% |

当前 2026 评估：胜平负约 **48.2%**，单场推荐约 **58.3%**，推荐≥65% 约 **61.0%**，推荐≥70% 约 **67.5%**。

---

## 二、每次调整都要做好的对比流程

以后任何一次改参数（校准、伤停、联赛参数、高置信门槛等），建议按下面做**对比**，避免命中率倒退。

### 1. 导出「调整前」基线（before）

```bash
python3 main.py jc-predictions-eval --year 2026 --export-baseline data/jc_eval_baseline.json
```

（若只关心某几年，可把 `--year 2026` 换成 `--all-time` 或 `--date-from/--date-to`，并给 baseline 起不同文件名。）

### 2. 做参数修改

- 校准：`calibrate-probs [--by-competition] [--train-date-from/--train-date-to]`
- 伤停：`lineup-key-absent-analysis --years ... --export-injury-params data/jc_injury_weights.json` → `merge-injury-params --injury-params data/jc_injury_weights.json`
- 联赛参数：直接编辑 `data/predict_league_params.json`
- 高置信门槛：改 `config.py` 或 `.env` 中的 `JC_REC_HIGH_CONFIDENCE_MIN_PROB`

**若动到校准或联赛/伤停参数，必须重跑预测：**

```bash
python3 main.py predict-jc-from-self-improvement --year 2026 --include-finished
```

### 3. 导出「调整后」基线（after）

```bash
python3 main.py jc-predictions-eval --year 2026 --export-baseline data/jc_eval_after_XXX.json
```

### 4. 对比

```bash
python3 main.py jc-eval-compare --before data/jc_eval_baseline.json --after data/jc_eval_after_XXX.json
```

- 若**提升或持平**：保留当前参数，可将 `after_XXX.json` 作为新的 baseline 供下次对比。
- 若**下降**：回退参数，再重跑预测并重新导出基线。

### 5. 备份习惯

- 改校准前：`cp data/calibration_params.json data/backup/calibration_params.json.before_YYYYMMDD`
- 改联赛/伤停前：`cp data/predict_league_params.json data/backup/predict_league_params.json.before_YYYYMMDD`

## 三、单场推荐再提升方案（改推荐/模型，需对比）

在已完成联赛门槛、校准、伤停、ML 权重 0.45 的前提下，从当前命中率继续往上抬的可执行项。

### 1. 细分覆盖（segment-stats，无需重跑预测）

在「联赛×推荐类型×概率区间」细分里，命中率低于阈值的**让胜/让负**会改推为**胜/负**。

```bash
# 一键自动：导出细分 → 用细分再评估 → 提示启用
python3 main.py jc-segment-auto
```

或分步：`jc-predictions-eval --export-segment-stats` → `--segment-stats` 再评估 → 若提升则设 `JC_REC_USE_SEGMENT_STATS=true`。详见 [数据驱动自我提升.md](数据驱动自我提升.md)。

### 2. ML 修正层权重

当前 `PREDICT_OUTCOME_ML_WEIGHT=0.45`。可尝试 0.5，改完重跑 2026 预测并 `jc-eval-compare`；若下降则改回 0.45。

### 3. 按联赛训练 ML、联赛 DC/平局参数、xG

- 联赛专属 ML：`train-outcome-ml --competition-id <id>`，重跑预测并对比。
- 联赛参数：在 `data/predict_league_params.json` 微调 `PREDICT_DC_RHO`、`PREDICT_DRAW_BOOST_COEF`。
- xG：确保有 `api_football_statistics`，开启 `PREDICT_USE_XG=true`，微调 `PREDICT_XG_BLEND`。

每次只改一项，重跑预测后做 `jc-eval-compare`。

### 4. 已尝试结果（供参考）

| 项 | 结果 |
|----|------|
| 细分覆盖（2026 单年） | 无变化 |
| 细分覆盖（全量 + min_n=20） | 单场推荐略降，不采用 |
| 英超联赛专属 ML | 样本少，2026 无提升，已移除 |
| PREDICT_OUTCOME_ML_WEIGHT=0.5 | 部分指标略降，已固定 0.45 |
