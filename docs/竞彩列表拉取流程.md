# 竞彩列表拉取流程说明

点击「拉取竞彩列表」选择某日（如 2026-03-03）时，后端按以下步骤执行。

## 1. 请求体彩列表接口

- **接口**：`GET https://webapi.sporttery.cn/gateway/uniform/football/getMatchListV1.qry?clientCode=3001`
- **日期参数**（依次尝试，直到该日有数据为止）：
  1. `matchDate=260303`（6 位 YYMMDD，与体彩页「比赛场次日期」一致）
  2. `matchDate=2026-03-03`（YYYY-MM-DD）
  3. 不传 `matchDate`，拿全量后再按竞彩日过滤

## 2. 解析响应

- 读取 **`value.matchInfoList`**（若为对象 `{0:..., 1:...}` 会转成数组）。
- 按 **`matchInfoList[].businessDate`** 找到等于请求日（如 2026-03-03）的那一项。
- 取该项的 **`subMatchList`** 整段（不按子项 businessDate 过滤）；若为对象则转成数组。
- 每条子项解析出：主客队、比赛编号、match_id、赔率等，并带上父级的 **businessDate** 作为竞彩日写入用。

## 3. 逐场拉详情并落库

- 对解析出的每场用 **match_id** 调体彩详情接口（getMatchHeadV1 等）拿单场详情。
- 把列表里的 **businessDate**、**match_num**（周二001 等）写入详情后，调用 **jc_match_analysis_save** 写入 `jingcai_match_analysis`。
- 若某场详情拉取失败或被判为无效（如退款），则该场不会写入，最终「写入场数」可能小于「列表场数」。

## 4. 展示

- 列表页从 **jingcai_match_analysis** 按 **jc_date** 查该竞彩日，并排除「比赛编号为前一竞彩日」的错日数据（如周二不显示周一004）。
- 比赛编号优先用拉取时写入的 **list_match_num**，没有再用详情里的 matchNum。

## 请求无响应 / 只有 1 场（走回退接口）

若日志出现 **「[getMatchListV1] 请求无响应，使用回退接口」**，说明请求体彩 getMatchListV1 失败（返回 None），常见原因：

1. **网络不可达**：服务器访问不到 `webapi.sporttery.cn`（超时、DNS 失败、被墙等）。终端会打印 **「请求异常: ConnectTimeout」** 或 **「请求异常: ConnectionError」**。
2. **HTTP 非 200**：体彩返回 403/502 等，终端会打印 **「HTTP 403」**（或其它状态码）。
3. **SSL 错误**：终端会打印 **「请求异常: SSLError」**。

**处理建议**：在运行 API 的环境里为体彩请求配置代理（体彩域名在国内，海外或部分网络可能需代理）：

- 启动 uvicorn 前设置环境变量再启动，例如：
  ```bash
  export HTTPS_PROXY=http://127.0.0.1:7890
  python3 -m uvicorn api.app:app --reload
  ```
- 或命令行按年拉取时加代理：`python3 main.py jc-batch-year --year 2026 --proxy http://127.0.0.1:7890`
- 若 getMatchListV1 始终无响应，可按年拉取时加 `--use-result-api`，历史日期将直接使用赛果接口 getUniformMatchResultV1，不再先请求 getMatchListV1：`python3 main.py jc-batch-year --year 2026 --use-result-api --sleep 5`

代理会优先使用 `set_sporttery_proxy` 或环境变量 `HTTP_PROXY` / `HTTPS_PROXY`。

## 如何排查「只有 1 场」

- **看接口返回**：拉取完成后提示会变为「竞彩日 xxx：列表解析 N 场，写入 M 场」。
  - 若 **N=1**：说明 getMatchListV1 解析只得到 1 场，需看体彩接口是否只返回 1 场或 businessDate 是否对得上。
  - 若 **N=12 且 M=1**：说明列表 12 场正常，但有 11 场在拉详情或落库时失败，可看 API 服务终端日志里是否有异常。
- **看终端日志**（用命令行或看跑 API 的终端）：
  - `[getMatchListV1] 竞彩日 2026-03-03 解析到 12 场` → 列表解析正常。
  - `列表 12 场，写入 1 场` → 列表 12 场，只有 1 场成功写入，其余多为详情接口失败或 is_invalid_match 过滤。
